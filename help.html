MaskLabel Help

Welcome

MaskLabel is an interactive image-segmentation and annotation tool built on SAM3. It runs entirely on-device — nothing about an image or its masks ever leaves this Mac. The only thing it downloads is the SAM3 model, once, the first time you start it.

  1. Open an image or a folder (details).

  2. Click the things you want to label (details).

  3. Name them (details).

  4. Save (⌘S; details).

Note

First launch: MaskLabel downloads the SAM3 model by itself as soon as it starts, so connect to the internet and leave the app open. The status bar shows “Downloading model… N%”, then “Unzipping model…” and “Loading model…”. Clicking to mask and Find Objects work once it finishes. If it fails, the toolbar shows the reason and a Retry button. It happens once; after that the model loads from disk in a moment. Details, and what to do if it fails: details ▸ First launch: the model download.

Tip

Use the sidebar to jump to any topic later. Customize shortcuts with the toolbar's Customize Shortcuts button; the fixed ones are listed at the bottom of that panel and under Reference ▸ Keyboard Shortcuts.

MaskLabel Pro and Free Mode

MaskLabel is free to start: the first 30 days include everything. After that it keeps working in Free Mode, and MaskLabel Pro unlocks the AI tools that run across a whole folder. There are no nag screens, no limit on how many images or masks you label, and your annotations are never locked away: you can always open, edit, save and export your own data.

Always free

  • Click-to-segment with SAM, boxes, Polygon and Pixels masks, the Layers table, classes and the Annotation Editor.

  • Find Objects with AI on the current image, by name or by example with Find Similar (details).

  • Convert Boxes with AI on the current image, and the sparkles button on a single box's row in the Layers table.

  • The Image Browser, Edit Split, copying subsets and every shortcut.

  • YOLO, COCO and Ultralytics NDJSON import, and Export to YOLO and Export COCO.

What Pro adds

  • Find Objects in Folder — the Find Objects search run across every image of the folder (details).

  • Refine Boxes with SAM — turn the boxes of an imported dataset into polygons, folder-wide (details).

Evaluation period

The 30 days start the first time MaskLabel runs (or when it was first downloaded from the App Store, whichever is earlier), and everything is unlocked until they end. Open MaskLabel ▸ MaskLabel Pro… to see how many days are left. In Free Mode, starting a Pro feature (the menu items and the buttons in their sheets) opens the MaskLabel Pro window instead; nothing else changes.

Buying, restoring and cancelling

  • One-time purchase — pay once; it doesn't renew, and it unlocks MaskLabel Pro in every future version.

  • Monthly subscription — renews automatically each month until you cancel it at least 24 hours before the end of the period. Cancel or change it from Manage Subscription… in the MaskLabel Pro window, or in your Apple ID account settings. If you cancel, Pro stays unlocked until the end of the period you already paid for.

  • Restore Purchases — in the same window, for a new Mac or a reinstall. Purchases belong to your Apple ID and need no key or account in MaskLabel.

Note

Purchases are handled entirely by the App Store: MaskLabel never sees your payment details, and an image or mask never leaves this Mac because of them.

1. Opening Images

  • At a glance — 1 image → that image · 1 folder → that folder (YOLO / COCO labels imported; a folder of folders is merged) · several images and/or folders → one collection of exactly those items, with the labels of any YOLO / COCO items · images already in the open folder → go to the first one. Annotations are saved in the folder for a folder, and in the app's collection store for a collection — the Image Browser header shows a collection's name with a “Collection” label.

  • Three simple rules — File ▸ Open… (⌘O), the Open… toolbar button and drag and drop all follow the same rules: one image opens that image, one folder opens that folder, and several items open as one collection of exactly those items.

    Nothing else is guessed. The Open… panel picks images, folders and .ndjson files, any mix, and you can select several, exactly like dropping them; a drop works on the window or on the image itself, and an outline around the window shows it will accept the drop (no outline appears while opening is paused).

    Opening is paused (a drop beeps) while an operation is running or a message is waiting for your answer.

  • One image — opens on its own: no folder and no Image Browser. If a folder is open and the image is one of its images, you simply go to it; if it is not, it replaces the open folder or collection, like opening a different folder does: the current image is autosaved, the image opens on its own, and the folder stays in Open Recent. A file the app can't read gives a message.

  • One folder — opens every image in it, shows the Image Browser and jumps to the first image (Open Recent does the same). A YOLO or COCO export is recognized and its labels imported; so is one split's image folder of such a dataset (for example train/images), which opens with the dataset's labels. A folder of folders is merged into one dataset (below). Step through the images with ← and →, or browse thumbnails with the toolbar's Image Browser button.

  • Several items — they open as one collection of exactly the items you picked, even when they are all from one folder; open the folder itself to get everything in it. The exception: images that are all in the folder (or collection) already open take you to the first of them (first by name, not in drop order), because their annotations are saved there. This applies only when every dropped item is one of those images; if a file that isn't an image or folder came along, the drop opens as a new collection instead. Details under Several items at once.

  • Opening replaces — what you open replaces what is open (except the folder or image that is already open: opening it again, by panel, drop or Open Recent, just shows the Image Browser or leaves your image as it is — unless it is a YOLO or COCO dataset whose labels were never imported, for example because you deleted its annotations folder: then they are imported again).

    The current image is autosaved first, and opening starts the canvas and classes fresh; opening a different folder, collection or an image outside the open folder never asks.

    The questions you can get are more than 20 folders, and an .ndjson file mixed with other items (you are asked whether to open just the first item).

    Before opening a different dataset, Close Folder (⌘⇧W, customizable in Customize Shortcuts) returns the window to its empty starting state. An Ultralytics .ndjson dataset file can be dropped too.

  • Open Recent (R) — lists the folders you've opened lately, with their image and annotation counts. Picking one opens it at its first image and shows the Image Browser; picking the folder that is already open (the one with the checkmark) just shows the Image Browser without reloading or moving you off your image.

    A folder that has been moved, renamed or deleted, or whose disk isn't connected, gives a message instead of replacing what's open, and is removed from the list.

    Only folders are listed, not single images; a collection (see Several items at once) is listed under the name of its first item (in alphabetical order, not drop order) followed by “+ N more”.

    The toolbar's Open Recent button opens the same list; it is unavailable while an operation is running or when the list is empty. Up to 10 folders are kept; the oldest drops off when a new one is added.

    Esc or a click outside closes it, and Clear Recent Folders empties it.

  • Folders of folders — a folder with no images of its own but two or more image folders inside it (named anything, like a dataset's train/valid/test) opens as one dataset, with those folders merged in name order. Only the folders directly inside are used. Opening more than 20 folders asks first. If the same filename is in more than one folder, each image keeps its own annotations (see Images with the same name); if some already share one saved file, you are told which names.

  • At launch — MaskLabel reopens the last folder and the image you were on, with its annotations. While that happens the canvas says “Loading…” instead of showing the drop prompt.

    The Annotated chip and class filter fill in from the last scan right away and settle once the folder has been re-read. If the folder's disk isn't connected, or the folder was moved, nothing opens, but the folder is remembered: reconnect it and relaunch.

    If the last image is gone, or lies outside the folder, the folder's first image opens instead. Open Recent fills in a moment after the window appears. Close Folder returns to the empty starting state.

  • Window size and position — the first time MaskLabel starts, its window opens centered on your main screen at a comfortable size: 90% of the screen's usable area (the part not covered by the menu bar and Dock), but no larger than about 1280 × 820 (and never smaller than 600 × 600, which is also the smallest size you can resize the window to).

    These numbers describe the window's content, so the window itself is slightly taller because of the title bar and toolbar, and macOS shrinks it if the screen is too small. macOS saves the window's size and position whenever you move or resize it, so from the second launch on it reopens as you left it (if a screen was disconnected in between, macOS moves the window back onto a screen that exists).

    To go back to the first-launch size, see “Start fresh” in Cache Files; that also resets your settings.

  • Alerts — messages from the app appear as a card in the middle of the window. Press Enter for the highlighted (blue) button and Esc to cancel. While one is showing, opening images or folders is paused until you answer it.

  • Image name — the name of the open image (with its extension) is shown centered in the window's title bar, and is also the window's title in the Window menu; with no image open the title bar says “MaskLabel”.

    Next to the name is the image's size in pixels (for example 4000 × 3000) — the same pixel grid your masks and exports use, with the photo's rotation already applied.

    Long names are shortened in the middle but the size is always shown in full; press C (customizable) to copy the complete name. The name is display-only, so you can drag the window by grabbing it, or double-click it to zoom or minimize, like any other part of the title bar.

    Full screen — View ▸ Enter Full Screen (⌃⌘F) enters it and the same command leaves it. The title bar is hidden there; move the pointer to the top edge of the screen to slide it down and see the image name and size. C still copies the name.

Several items at once

One collection — a single dataset made of exactly the items you picked. Nothing is copied or moved. Several images from one folder open only those images; several folders open only those folders (a dropped train, valid or test folder of a YOLO or COCO export counts as its images, so its labels come along). To get every image of a folder, open the folder.

Where annotations are saved — a folder keeps its annotations in its own annotations folder; a collection keeps them in a folder the app maintains for it (~/Library/Application Support/MaskLabel/Collections). The same images therefore have separate annotations depending on whether you opened their folder or picked them as a collection.

Remembered and labeled — a collection remembers where each item is; nothing is stored next to your images. Folders that share a name get separate annotation files for repeated image names. If an item is a YOLO or COCO export — or some of its splits — its labels are imported too, once, in the background and only for the images you dropped, with the usual import progress in the Image Browser (Cancel stops it; reopening the collection resumes it, also after a missing folder or drive is back).

Class names from different datasets are merged by name, and images you already annotated are never overwritten. Dropping the same selection again reopens the same collection with its annotations; adding or removing an item makes a new collection, which starts without the annotations you made in the old one; the earlier collection keeps its own and reopens when you drop its exact selection again.

Limits — items from more than 20 different folders ask you to confirm. Folders without images are skipped and named in a message. If an item of a collection is later moved, renamed or on a disconnected volume, you are told and the rest still opens. An .ndjson dataset file dropped with other items asks “open the first item?” and ignores the rest. One image or folder next to files that can't be opened simply opens, and two or more images and/or folders open as a collection; either way a message says how many other items were ignored.

While SAM is working (extracting an image's features, converting boxes, Refine Boxes…) opening is paused: dragging files over the window shows a dashed orange "Can't open files right now" notice with what it is doing, instead of the blue outline, and a drop is refused. Drop again when it has finished.

Good to know — while an export is still writing into the open folder, opening or dropping another folder, or an image from outside it, is refused with a message. Opening another folder while images are being moved between splits stops that move after the image in flight. A drop or a menu open while another message is waiting for your answer is ignored (a drop beeps).

Folders reached through a symlink or alias open like regular ones. A dropped file that isn't an image, a folder, or an .ndjson file is reported instead of silently ignored. If only some of the dropped items can be read, you are asked whether to open the rest. If none of the dropped items can be read at all (for example a source app or disk that stops responding; the app gives up after about 10 seconds with nothing arriving), you get a message instead of nothing happening.

Rescanning and closing

Rescan Folder (⌘R) re-lists the open folder's images and re-reads its annotation files from disk. It's the only way, short of closing and reopening, to pick up images or annotations changed outside the app. An image with masks or unsaved edits is never replaced; an open image with neither also picks up an annotation file that appeared on disk.

Close Folder (or Close Image for a single loose file) releases the dataset and returns the window to its empty starting state. It doesn't quit the app or close the window itself. It has no menu item: it is a customizable shortcut (default ⌘⇧W), listed in Customize Shortcuts. Closing while a YOLO import or an Ultralytics .ndjson download is still running stops it (images already downloaded stay, and importing the same file again resumes), and a batch image move (moving images between train/valid/test) stops after the image in flight; images already moved stay moved.

While an export is still writing, Close Folder is unavailable until it finishes, and opening an image from outside it is refused with a message. Closing also means the app starts empty at the next launch instead of reopening that folder; the folder stays in Open Recent.

2. Segmenting an Object

Move the cursor over the object: before you click, a live preview shows the mask a click at that spot would give you (its color is the Hover Mask Color and its opacity the Mask Opacity, both in Display Options). Click to lock it in as your first point. SAM3 then predicts the mask, and the Annotation Editor opens automatically so you can name what you just clicked.

Refining the mask

  • Green point — click elsewhere on the object to add another region to the mask.

  • Red point — click inside the current mask preview to carve out a region you don't want.

  • Box — press on the image and drag, instead of clicking, to draw a box around the object; SAM finds the object inside it, and a live preview of what it finds follows your drag, so you see the result before you let go (the Annotation Editor then opens like after a first click).

    Use it when a click picks only part of the object, or the wrong one. A box works as the first prompt or after some clicks, and clicks after it refine the mask as usual (outside the preview adds, inside carves out).

    A mask holds one box; ⌘Z removes it in one step, like a point, so you can draw another. With clicks already placed, the preview includes them and the current mask, exactly like the mask you get on release.

    A press that moves only a few screen points is an ordinary click, and a drag that is too small for SAM counts as a plain click where you pressed (“too small” uses the same Skip boxes smaller than setting as Refine Boxes with SAM, so changing it there changes this too), and Esc while dragging cancels the box.

Note

You don't choose add or subtract yourself. It's decided automatically by whether the click landed inside or outside the current preview. In Polygon mode that test uses the polygon outline you see on screen; in Pixels mode it uses the filled mask.

  • Clicking an existing mask — when no new mask is being built, a click that lands on a saved mask selects that layer and opens it in the Annotation Editor instead of adding a point (unless you switched Open Editor on Layer Click off, see Display Options). Only a plain click selects the layer: a drag that starts on a saved mask draws a box (except while a saved mask is open for editing with the Annotation Editor closed).

  • Clicks while it's working — a click or box drag that arrives while a prediction is still running, while a mask is being saved, or before the image has finished preparing, is ignored (a released box also beeps); wait for the mask to appear (or for the preview to start following the pointer), then click again.

    Save (Enter) is refused the same way while a click's prediction is still running: it beeps and the Save button is dimmed until the mask appears, so you never save the previous mask by mistake.

    Esc or Reset Points is the exception: it works while a click's prediction is running and throws that prediction away.

  • Hide Mask Hover — with this switched on in Display Options (or its shortcut, default V), clicking empty canvas or dragging a box does not start a mask at all, because there is no preview to click on. Switch it off to segment; clicking a saved mask still selects it.

Tip

Esc clears every in-progress click point and closes the editor without saving anything, so you can back out of a mask that isn't working and start over (the same as the editor's ✕, and the same as the Reset Points button).

It also works while a click's prediction is still running (that prediction is thrown away, so no mask appears afterwards). After a reset, and after you save a mask, the live preview returns under the pointer on its own.

If the “box → polygon” notice is showing, the first Esc only dismisses that notice. Resetting can be undone: one ⌘Z brings back all the cleared points (and the box, if you had drawn one) together, and each further undo removes one point at a time.

Zooming and panning

  • Pinch on the trackpad, or hold ⌘ or ⌥ and scroll, to zoom around the pointer. Scrolling without them pans the image, and so does dragging with the middle mouse button. With a mouse wheel, the wheel alone pans; each notch pans by a fixed distance (about 40 points), or zooms by about 13% with ⌘ or ⌥ held. Without a middle button or a trackpad, hold Space over the image and drag to pan; the pointer becomes a hand, a click while Space is held places no point, and Space is left alone while you type in a text field or while ⌘, ⌃ or ⌥ is held.

  • Whether a scroll zooms or pans is decided when the gesture starts, so releasing ⌘ or ⌥ partway through a trackpad flick doesn't turn the rest of it into a pan. A zoom stops the moment your fingers lift; it doesn't keep coasting on the trackpad's momentum.

  • Zoom In / Zoom Out from the keyboard (⇧= and - by default; ⇧; on a JIS keyboard) zoom in steps of 25% around the pointer when it is over the image area (around the center of the canvas otherwise), and holding the key keeps zooming. The keypad + and − keys and ⌘= / ⌘- (the ⌘+ and ⌘- of most Mac apps) zoom the same way; they are always on, can't be customized, and give way to any shortcut you have set on the same key (a bare keypad key still types into text fields). Zoom Focus (Z) fits a mask's bounding box in the window; see Keyboard shortcuts for which mask it uses.

  • Reset Zoom (0 or the toolbar button) fits the whole image in the window again and re-centers it. Actual Size (⌘1) shows one image pixel per screen pixel, even for a very small image that the window fits at a large size. On a trackpad, a two-finger double-tap (Smart zoom) zooms to Actual Size around the pointer, and a second double-tap returns to the zoom level and position you had before (or to fit-to-window if Actual Size was reached another way, such as ⌘1), when Smart zoom is turned on in System Settings ▸ Trackpad.

Note

Every zoom change briefly shows the zoom level in a small “NNN%” badge in the bottom-left corner of the canvas, where 100% is Actual Size (one image pixel per screen pixel). It fades after a moment and doesn't appear when a different image opens.

Note

After you zoom or pan and stop for a moment, the live preview under the pointer refreshes by itself, so it always matches the spot a click would land on — you don't have to nudge the mouse first.

Note

A three-finger swipe on the trackpad moves to the previous or next image in the folder. It is ignored while you are in the middle of an edit (placed points, a polygon, or a running prediction), so an accidental brush can't discard your work.

Note

Zoom is limited to a quarter of the fitted size at the smallest (or Actual Size, if that is smaller) and 60 times at the largest (or 64 screen pixels per image pixel, if that is smaller, so a very small image can't be enlarged without end). Opening a different image always starts it fitted to the window. Resizing the window or dragging a divider keeps the same part of the image centered. The image can't be panned completely out of view — a strip of it always stays on screen — and Reset Zoom (0) recenters it whenever you want. The zoom shortcuts and the Reset Zoom button do nothing while the image browser is open, and a bare-key Reset Zoom shortcut is also paused while the Annotation Editor is open.

3. Naming and Saving a Mask

  1. Name the class in the Annotation Editor's text field. Type a brand-new name, or start typing to search existing ones — the list below the field narrows to names that start with what you typed (upper and lower case don't matter) — and use ↑ / ↓ to move through the matches; the selection wraps around at the ends, and ↑ with nothing selected goes to the last match.

    Scrolling the list with the mouse or trackpad only browses; it never changes the selection. Every class also has a number shown on its row (0 = first alphabetically): type that number in the field — including numbers above 9, and full-width digits from a Japanese keyboard — to pick the class directly.

    Names that start with those digits are listed too, but the class at exactly that position is the one highlighted.

  2. Press Enter (or the Save (Enter) button) to commit the mask as a new row in the Layers table, colored to match its class.

Tip

Every class has a number based on where it falls alphabetically, shown next to its name. Typing that number in the field jumps straight to the class — faster for names you reuse constantly. The numbering counts every class in the dataset, used or not, and is the same order the Classes sidebar uses. If your classes are named with numbers (0, 1, 2 … 10), remember the shortcut is the alphabetical position, not the name — "10" sorts before "2" — so check the highlighted row.

Tip

Clicking a row in the editor's class list saves the mask with that class straight away — the same as typing its name and pressing Enter. The list scrolls and stays quick even with thousands of classes.

Note

Delete discards the whole in-progress mask instead of saving it. If you opened a saved mask to edit it, Delete removes that mask. If you opened a class, Delete removes the class and every mask that uses it on the current image; the class moves to Unused.

Both can be undone with ⌘Z. Hover over Delete to see what it will remove. ⌘D (the default for Annotation Editor Delete, changeable in Customize Shortcuts) presses the Delete button at any time, even while the name field has text.

With no mask open for editing, a highlighted class that no mask uses is removed by the Delete button or ⌘D instead (not by ⌫, so a stray key press can't remove it). While Save is finishing (the mask is still being committed), Delete, ⌘D and ⌫ are ignored, and so is a second Enter.

Tip

Pressing ⌫ once the name field is empty does the same as Delete. Holding ⌫ to wipe a name just clears the text; it never deletes the mask by itself, and neither does a ⌫ pressed right after the field was emptied, while an input method (such as Japanese) is composing text, or together with ⌘, ⌥, ⌃ or ⇧ (so ⌘⌫ still means Clear All Masks).

Esc closes the editor without saving — except while an input method (such as Japanese) is composing text, when it only cancels the composition.

After moving with ↑ / ↓, the highlighted row stays selected even if you clear the field, so ↩ still saves under it. ⌫ on the empty field then discards the in-progress mask (or deletes the mask or class you opened); it never removes a highlighted unused class — use the Delete button or ⌘D for that. ↑ / ↓ are left to the input method while it is composing text (such as Japanese), so they choose conversion candidates instead of moving the highlight.

Tip

⌘Z / ⌘⇧Z also step through what you typed in the name field, together with your mask edits and in the order they happened. Typing is undone one burst at a time (a pause of under a second ends a burst), and a run of ↑ / ↓ presses is a step of its own — typing right after the arrows is a separate step, not merged into it. This typing history is dropped when the editor closes or you open another row, so a saved name is then undone as part of the mask.

Tip

The class list shows up to 10 rows at a time and scrolls beyond that. In a short window it shows fewer, so it never runs underneath the Mask Options panel.

4. Polygon vs. Pixels

  • Polygon — saves an editable point outline. The Simplify slider trades point count for a tighter fit: drag toward Simple for fewer points or Complex for a closer outline. The label above the slider shows how many points (“N pts”) the current mask would get at that setting. The slider only appears in Polygon mode.

  • Points tab — on a saved Polygon mask, the first tab of the Polygon panel is the basic point editor. The panel opens on the tab you used last (Points the first time); your choice stays as you move from mask to mask.

    Drag a point to move it. Click a point to delete it (a polygon keeps at least 3 points). Press on an edge and drag to add a point and move it in one motion; a plain click on an edge adds a point where you clicked.

    A press that moves only a pixel or two still counts as a click. While SAM is still working (a moment on large images), point edits are refused with a note under the panel instead of being ignored; try again when it clears.

    Clicking empty image never starts an outline: it selects the mask under the click, if there is one, so you can move on to another polygon without the Layers list.

  • Several points at once — drag a box around them, or ⇧-click points to add or remove them. Selected points turn blue, dragging one of them moves them all together, and ⌫ or the Delete N selected button removes them as one undo step (Esc clears the selection). A polygon still keeps at least 3 points.

  • Nudge with the arrow keys — with points selected, ← ↑ → ↓ move them by 1 image pixel and ⇧ + an arrow by 10 pixels, for exact edge placement.

    While points are selected the arrows do this instead of stepping to the previous / next image; press Esc to clear the selection and they step images again.

    The selection stops at the image edge, and a nudge that would make the outline cross itself is refused like a drag (beep and a red line under the panel).

    A run of nudges (or a held key) is one undo step with ⌘Z, which also brings the selection back. With one corner of a plain rectangle selected, the box is resized and stays rectangular.

    The arrows are left alone while the Annotation Editor or Image Browser is open, while you type in a text field, and with ⌘, ⌃ or ⌥ held.

  • Simplify selection — with 3 or more points selected, this button (above Delete N selected) runs the same simplification as the Simplify button, but only on the selected points.

    Each stretch of neighbouring selected points keeps its first and last point, so the line joins the untouched part of the polygon exactly where it did before; the points in between are thinned out, so you can clean up one over-dense edge (for example a staircase left by a SAM click) without touching the rest.

    Like Simplify, it has 2 presses per selection (the 2nd goes further) and shows the result before you click (for example “100 → 92”); the remaining points stay selected, and each press is one undo step.

    If you select every point, it does exactly what Simplify does. Undo brings back the removed points and the selection (the same goes for Delete N selected).

    It is disabled once both presses are used, or when the selection has no stretch of 3 or more neighbouring points, or nothing in it can be removed without making the outline cross itself.

    The 2 presses count per selected area: select a different area (or edit the polygon in any other way) and you can simplify again. Moving the selected points as a block (dragging them, or nudging with the arrow keys) does not change the number the button previews, because the selected stretch keeps its shape; the Simplify button, which looks at the whole outline, can still change.

  • Simplify button (Points tab) — removes points using the same RDP as the Simplify slider, in at most two presses. It shows the result before you click (for example “100 → 60 pts”) and keeps the points that remain exactly where they were, including along the edge that closes the outline.

    The original polygon is remembered, so press 1 re-simplifies those original points to halfway between the original point count and its simple (convex) outline, and press 2 goes to 25% of the way.

    Each press is one undo step. After press 2 the button does nothing until you edit the polygon (a new series starts then). It is also disabled if the polygon is already at the 25% level, or if it can’t get simpler without crossing itself.

  • Point edit rules — a polygon keeps at least 3 points and can’t be made to cross itself. Each edit is one step you can undo with ⌘Z. While you drag — one point or a whole selection, on any polygon size — the polygon turns red if letting go there would make it cross itself; move to a spot where it turns normal again to apply the change.

    If you release while it is red, the change is refused: you hear a beep, the point snaps back, and a red line under the panel says why. The Simplify button follows the same rule: it never produces an outline that crosses itself.

    When you are zoomed far out, points closer than a few pixels apart are drawn as one, but every point can still be grabbed. A polygon that already crosses itself (an imported one, for example) can still be edited point by point, but only in ways that don’t add crossings: the polygon turns red when a move would add one, and the same refusal applies on release, so you can untangle it step by step.

    On a plain rectangle (a box that hasn’t been converted yet), dragging a corner resizes the box and keeps it rectangular.

  • Draw, Erase and SAM tabs on a Polygon mask — these don’t grab or insert points; use the Points tab for that. The one exception: hold ⌥ and the tab edits points without leaving it.

    Over a point the cursor becomes a hand: click deletes it, drag moves it. Over an edge it becomes a plus: click adds a point, drag adds one and moves it.

    Each is undoable with ⌘Z. A polygon needs at least 3 points, a move that would make the outline cross itself is refused, and it does nothing while an outline is in progress, while a multi-point SAM refinement is pending (⌥ then flips a point between + and − instead), or while masks are hidden.

    On the SAM tab, click outside the polygon to add an object, or inside it to remove part of it. Green shows what a click will add, red what it will remove.

    SAM’s outline is traced with the same Simplify slider (shown on the SAM tab too) and merged into the polygon the way a Draw / Erase outline is: only the points where it meets the polygon change, all the others stay where they are.

    Whether the result joins the polygon or becomes a new row is explained under What a SAM click does to the shape, below. A click near an edge goes to SAM; switch to the Points tab to edit points.

  • What a SAM click does to the shape — an object that touches the polygon, or lies no more than about 2 pixels from it, is merged in (a tiny bridge closes that small gap); one farther away becomes its own row.

    If SAM finds several separate pieces, all of them are applied in one undo step, and a small note under the panel tells you if a piece was left out because its outline was too thin to be a polygon (for areas you add and for areas you cut alike).

    A cut that splits the polygon leaves the largest piece in the row and the rest as new rows below. A cut can’t leave a hole inside the polygon.

    When the traced outline would touch itself (usually a link only one or two pixels wide), the SAM tab retries with such thin parts removed from the mask, so a thin neck may be trimmed away; undo with ⌘Z if that isn’t what you wanted.

    If a click is still refused, a red line under the panel says why (for example the new outline would touch itself — try another Simplify level or a slightly different spot).

  • Several SAM points on one object — hold ⇧ and click on the SAM tab (or drag a box around the object) to start a refinement instead of a one-shot click: the first point finds the object, and every further click (the ⇧ is only needed for the first) adds a point to the same prediction.

    A click outside the green or red preview adds a positive point (SAM includes that area too); a click inside it adds a negative point (SAM leaves that area out).

    Hold ⌥ while you click to flip that choice for the point: ⌥-click outside the preview adds a negative point, and ⌥-click inside it adds a positive one.

    The cursor shows + or − to match, and it updates as you press or release ⌥. The first point is always positive, so ⌥ only applies from the second point on.

    The dots show your points (green positive, red negative) and the preview updates after each one (pieces that would be saved as a separate mask are orange here too).

    Cancel and Apply appear under the preview while points are pending; Undo and Redo are ⌘Z / ⇧⌘Z and the toolbar buttons. Nothing changes in the polygon until you press ↩ or Apply; ⌘Z removes the last point and ⇧⌘Z puts it back; Esc or Cancel drops them all.

    Switching to another tab and back keeps the points and their undo / redo, as long as the polygon itself wasn't changed in between. Applying is one undo step and follows the same merge, cut and Simplify rules as a single SAM click.

    While SAM is still working on a prediction, Apply is refused with a beep and a note under the panel (“SAM is still working on this mask — try again in a moment.”); try again when it clears.

    Undoing an Apply brings every point and the predicted preview back (instead of only reverting the polygon), so you can keep adjusting; ⇧⌘Z applies it again. It works the same way on a Pixels mask.

  • Drag a box on the SAM tab — press on the image and drag instead of clicking to draw a box around an object; SAM then finds the object inside it.

    Use it when a click picks only part of the object, or the wrong one. While you drag, a live preview shows what SAM finds in the box right now (green adds, red removes), so you see the result before you let go; it is not shown while Hide Mask Hover is on.

    Esc while dragging cancels the box, and so does starting to pan with Space. Releasing the box starts the same pending refinement as a ⇧-click: the preview shows green (add) or red (remove), and ↩ or Apply commits it, Esc or Cancel drops it.

    A box always adds what SAM finds in it, even when it overlaps the mask, which is how you complete a missed part such as a leg. To remove instead, hold ⌥ while you drag or when you release the box: the box (and its live preview) is green when it will add and turns red when it will remove.

    After the box you can click to refine: a click outside the preview includes that area, a click inside it leaves that area out (⌥ flips it).

    A refinement holds one box; to try another box, press Esc first. A box that is too small for SAM is refused with a line under the panel; the minimum size is the same one as the Refine Boxes option, so changing it there changes it here too.

    The box and every click are undo steps (⌘Z). Dragging never moves a polygon point; hold ⌥ to edit points as before.

  • Simplify on the SAM tab — sets how many points the outline traced by your next SAM click gets: toward Simple for fewer points, Complex for a closer outline. It does not change the polygon as it is now. Each SAM click is one undo step.

  • What Esc does — one step at a time, in this order: it drops pending SAM points; then an unfinished outline; then the selected points; then it closes the Annotation Editor; and finally it leaves Polygon editing. ↩ applies pending SAM points, otherwise it finishes the outline (when the Annotation Editor is closed).

  • Pixels — saves a filled raster mask instead.

Note

The Simplify slider is one shared setting: the copy on the Polygon panel's SAM tab is the same slider as the one in Mask Options, so moving it there also changes how the next new Polygon mask is traced, and the Outline detail choice in Refine Boxes with SAM and Find Objects in Folder. Trying to remove a point from a 3-point polygon is refused with a beep and a red line under the panel.

Tip

If the Simplify button on the Points tab is greyed out, the polygon is already at the 25% level, both presses have been used, or removing more points would make the outline cross itself. Edit the polygon (move, add or delete a point) to start a new series, or undo with ⌘Z to step back to an earlier press. While the label shows only “N pts” without an arrow, the result is still being worked out.

Editing a Pixels mask — select its row in the Layers table and the Brush Polygon panel appears. You edit the mask by outlining areas to add or remove, and by clicking objects with SAM (hold ⇧ on the SAM tab to refine one object with several points, or drag a box around it). Subtract Others, at the bottom of the panel, then trims the parts that overlap other masks.

An outline that would change nothing is discarded with a beep and a red “Nothing changed.” line under the panel (⌘Z brings its points back); an outline that would erase the whole mask is refused with a beep and a red line that says why, and stays on screen so you can adjust it; a SAM click that would add nothing, remove nothing or empty the mask is refused the same way.

While SAM is still working on a click (a moment on large images), outline clicks, further SAM clicks and ↩ are refused the same way, with a line saying SAM is busy, instead of being ignored; the line goes away by itself when SAM is done. If the pointer preview is still running when you click, the click is not lost silently: a line asks you to click again. A mask whose size doesn’t match the image can’t be edited with SAM; a line says so instead of only beeping.

Subtract Others — a button at the bottom of both the Brush Polygon panel and the Polygon panel. It removes from the selected mask whatever other visible masks (same image) already cover, so the masks stop overlapping and the selected one gives way. A Pixels mask has those pixels cleared. A Polygon mask is cut along the other outlines, so only the overlapping part changes, and pressing the button again changes nothing.

If the cut would leave a hole inside a polygon, or remove the whole mask, nothing happens and a red line says why; a cut that splits a polygon leaves the largest piece in the row and the rest as new rows below. Hidden masks (eye icon off) are ignored. One undo step with ⌘Z.

  • Outline an area — click points on the image, then close the shape by clicking the first point (or press ↩ when the Annotation Editor is closed, or use the Apply button).

    Esc throws away an unfinished outline. While you place points, a tinted preview of the area follows the pointer. To fix a misplaced point before closing, drag it to a new spot (a press that doesn’t move still counts as a click, so clicking the first point still closes the shape).

    ⌘Z removes points one at a time; moving a point of that unfinished outline is not a separate undo step (on a saved Polygon mask, every point edit is its own undo step). Each closed shape is one step you can undo with ⌘Z.

  • SAM tab — the third tab next to Draw and Erase. Click an object on the image: if you click outside the mask, everything SAM finds there is added to it (green); if you click inside the mask, it is subtracted (red).

    A live preview follows the pointer and shows exactly what the click would change — on a Polygon mask a piece that a click would save as its own separate mask is orange instead of green, so you can see before clicking whether it joins the polygon (it follows the pointer as fast as SAM can answer, and is instant over a spot you have already visited); nothing shows when it would change nothing (turn it off with Display Options → Hide Mask Hover).

    Each click is a separate prediction of the one object under the pointer — not a chain of points like making a new mask (⇧-click starts a multi-point refinement instead, and dragging draws a box for SAM to find the object in, with its own live preview) — and one undo step with ⌘Z; click elsewhere or undo if SAM picked too much or too little.

    Switching to SAM drops an unfinished outline, X steps back to Draw / Erase, and T switches to and from SAM: on a Pixels mask between Draw / Erase and SAM, on a Polygon mask between Points and SAM.

    SAM stays selected as you move from layer to layer (until you pick another tab), so you can refine one mask after another without re-selecting it.

    If SAM isn’t ready for the image, or a click would change nothing or empty the mask, you hear a beep. While the pointer is over a floating panel (this one included), the hover preview is hidden; move the pointer back onto the image to see it again.

    It also comes back by itself when a panel closes under a pointer that is resting on the image (for example when ⌘Z closes the Annotation Editor).

  • Esc and ↩ in the Brush Polygon and Polygon panels — each press backs out one level: first it drops pending SAM points (see Several SAM points on one object), or throws away an unfinished outline, then it clears selected points (Points tab), then it closes the Annotation Editor if it is open, and finally it closes the panel and stops editing the mask.

    ↩ applies the outline or the pending SAM points (when the Annotation Editor is closed). Both keys are left alone while you are typing in another text field or in another window. Nothing you already applied is undone; use ⌘Z for that.

  • Draw / Erase — Draw adds the outlined area to the mask; Erase removes it. Press X to switch between them without moving the mouse to the panel (the outline turns red in Erase; the key can be changed in Customize Shortcuts). An outline needs at least 3 points: pressing ↩ or clicking the first point with fewer than 3 keeps what you have and shows a red line saying so. Keep clicking, or press Esc to discard it.

  • Draw / Erase on a Polygon mask — the outline is merged into (Draw) or cut out of (Erase) the polygon's points, and the result stays an editable polygon.

    Draw merges the outline when it overlaps the polygon (a pocket the new shape closes off is filled, because polygons have no holes); an outline that doesn’t touch the polygon becomes a new row below it with the same class, just like a far-away object on the SAM tab, and ⌘Z removes that row again.

    Erase can't leave a hole or remove the whole mask; a cut that splits the polygon leaves the largest piece in the row and the rest as new rows below.

    An outline that crosses itself, or one that changes nothing, is refused with a red line under the panel. ⌘Z puts the outline back so you can peel its points off.

    Because these tabs don’t edit points, your first click of a new outline can be anywhere, including right on the polygon’s own edge, which is handy for trimming. Use the Points tab to move, add or delete points.

  • Edge accuracy — the fill includes every pixel the outline touches, so a shape can add or remove up to about one pixel beyond the line you see. An outline that crosses itself still fills everything it encloses, including the parts where it overlaps itself.

Tip

Undo keeps only the area each edit changed, so even on a large image you can step back through many outline and SAM edits.

Note

The Mask Options panel sets this while a new mask is being built. It only affects new masks going forward — switching modes never changes anything already committed, so it's fine to change your mind partway through an image.

Tip

The ✕ on the Mask Options panel hides it for the current mask. It comes back the next time the Annotation Editor opens for a new mask, or when you start Find Objects with AI.

5. Layers and Classes

  • Layers table — every committed mask on the current image is a row, newest at the top. Click a row to open it in the Annotation Editor (click it again, or press Esc, to deselect), where you can rename it, reassign its class, or delete it.

    If you only want to edit the mask itself (Pixels brush or Polygon points), press E first: clicking a row — or the mask on the canvas — then just selects it, with the editor closed, until you press E again (it switches back on every launch).

    Press ⌫ to delete a mask selected this way. The eye icon on a row shows or hides that mask, and dragging a row reorders the stack. Hovering a row isolates that mask on the canvas; moving to empty space in the table brings all visible masks back.

    Rows that are still plain boxes get a sparkles button that converts that box to a polygon with AI, and a Convert Boxes with AI button under the table does them all at once. The table stays responsive with hundreds of masks.

  • Classes sidebar — manages the shared list of classes and their colors, used consistently across every image in the folder rather than per image. Classes are listed alphabetically. Click a class to show only its masks and open the Annotation Editor on it, where you can rename it or change its color; click it again, or press Esc, to deselect. Hovering a class row shows only that class's masks on the canvas, and moving to empty space in the list brings all visible masks back. While a class is selected, its masks stay shown no matter which row you hover.

  • Unused Classes — below the main list, classes that have no mask on the current image but may still be used by other images in the dataset, or by no image at all (for example a class you renamed away from, or one imported with a dataset but not yet used).

    Each row has a Find Objects with AI (sparkles) button that searches the current image for that class, and a trash button that removes the class name from the list (undoable with ⌘Z).

    A class can only be removed when no other image uses it (images that share a name across splits or folders, such as train/a.jpg and valid/a.jpg, are checked together: if either uses the class it stays, and the pair is counted as one image in the number shown): if other images do, the trash button is disabled and its tooltip says how many (remove its masks there first).

    Remove All, at the right of the “Unused Classes” heading, removes every unused class that no image in the dataset uses, in one step; classes still used by other images stay, and one ⌘Z brings the removed ones back.

    Hover Remove All to see how many it will remove and how many will stay. Both are disabled while the folder is still being scanned, while a dataset import or label re-import is running, and while images are being moved or deleted (the class usage isn't final until those finish). Removing a class here only edits the app's class list: it never changes data.yaml, label files or exported class numbers (see Export YOLO).

    “Used by other images” means their saved annotations in MaskLabel; unsaved edits on the open image are never counted. A class that is still listed in an imported data.yaml can show up again as unused the next time you import, and an in-place export keeps it in data.yaml. To drop it from data.yaml, export to a new folder instead (that export lists only used classes). The rows themselves aren't clickable; to rename an unused class or change its color, find it in the Annotation Editor's class table. The list shows three rows at a time and scrolls for the rest.

  • Clear All Masks (⌘⌫, or the trash button in the toolbar) removes every mask on the current image in one step, with no confirmation. Press ⌘Z to bring them all back — but only until you open another image or folder, since undo history belongs to the image you're on.

    Classes that were used only by those masks move to Unused Classes. The button and shortcut do nothing while the image browser is open, while a mask is being committed or a prediction is running, or when the image has no masks.

    Like any change, the cleared state is saved to the annotations folder when you save or move to another image.

  • Undo (⌘Z) / Redo (⌘⇧Z) — cover the whole history (individual clicks, commits, deletions, and edits), not just the last thing you did.

    Brush Polygon vertices undo one at a time, pending SAM points undo one at a time too (undoing an applied SAM refinement brings its points and preview back, on Pixels and Polygon masks; undoing or redoing a SAM point also switches to the SAM tab, where it can be seen), and closing a polygon is one step: ⌘Z right after closing reopens it with all its vertices, and the next ones remove them one by one.

    After pressing Esc on an unfinished polygon, one ⌘Z likewise brings all its vertices back. Undo history belongs to the image you're on: opening another image or folder, or changing the annotations folder, starts it fresh (the one exception: a loose image whose masks were never saved keeps its masks and history when you change the folder).

    In a very long session on a large image the oldest steps may be dropped to save memory (normally at least the 30 most recent steps are kept; on a huge photo whose history is far over the memory limit, as few as 5).

    Undoing a Find Objects Save removes the masks it created and reopens the results panel with the same threshold; undoing a Save in the Annotation Editor restores the class name, but not the individual typing steps. Undo and Redo are refused (with a beep) while a prediction is running or a Save is still being processed (a moment on large images); press them again once it has finished.

    While you type in another text field (such as a filter box), ⌘Z / ⌘⇧Z only step through that field's own text and never touch your masks.

    Moving a point of an unfinished outline isn't a step of its own, but it does clear what Redo could bring back. The Mask Options settings (Polygon / Pixels mode and the Simplify slider) are not part of the history: ⌘Z never changes them, only the masks and text you edited.

Tip

With very many masks on one image, Polygon masks are lighter to edit than Pixels masks: undoing a point edit restores just the outline points, while each Pixels edit keeps full-image-size picture data. While an image is open, every mask (Polygon or Pixels) still keeps a full-size picture in memory, so hundreds of masks on a very large photo add up either way. Recoloring a class that has many Pixels masks takes a moment while they are repainted.

Tip

Hovering a class that has many Pixels masks waits a fraction of a second before showing them, so sweeping the pointer down a long class list stays smooth — rest on a row and its masks appear. Renaming or recoloring such a class repaints its masks in parallel but can still take a moment, and so does undoing or redoing a rename. Choosing a new class color is not an undo step. Hiding masks you aren't working on (or turning masks down with the Cycle Mask Visibility shortcut) also reduces what has to be drawn.

6. Find Objects with AI

For images with many repeated objects of the same kind — a tray of parts, a crowd, a shelf of products — Find Objects with AI proposes masks for a whole class at once instead of clicking each one individually. You can search by name (the steps below) or by example, by drawing a box around one object (see Find Similar after the tip).

  1. Pick a class. Type its name — any text works, it doesn't have to be an existing class — or choose one from the list with ↑ / ↓ or by typing its number, then press Return or Find Objects. The list shows every class, used and unused, in the same alphabetical order and with the same numbers as the Annotation Editor.

  2. Review the proposals. They are previewed together as one mask on the image, drawn in the Hover Mask Color. Drag the Confidence Threshold slider (Less Strict ↔ More Strict, 5%–95%, starting at 50% for every new search) to keep more or fewer of them; the count updates when you let go. Each kept object also shows its confidence as a percentage at the top-left corner of its box, the same number the slider compares against, so you can see where to set it. If you find 0 objects, lower the threshold or try a shorter, more specific name. Back returns to the search with your text still filled in. Esc closes the results and discards them.

  3. Save to open the Annotation Editor with the searched name filled in, so you can confirm or change the class. Saving then creates one layer per object in the Layers table in one step, as Pixels or Polygon masks according to Mask Options (an object that can't be traced into a polygon is saved as a Pixels mask instead). One ⌘Z undoes the whole batch and brings the results back with the same threshold. Return also saves while the results are showing.

  • Cancel while a search is running stops it and returns to the search with your text still filled in; Esc stops it and closes the panel. Either stops at the next step (text encoding, detection, mask cleanup): the step already running has to finish first, and its result is discarded.

  • Save is disabled while the results are still being recomputed after a slider change, and while a search is running.

  • Save can take a moment on a large photo with many objects: each object is cleaned up again at the photo's full size as it is saved. A second Save, undo or click is ignored until it has finished. The preview you review before saving is drawn from a smaller version of the masks, so its edges can differ very slightly from the saved result.

  • If a search fails (for example the model or the image isn't ready), a message appears at the bottom of the window and the search panel reopens with your text.

  • Switching to another image while a search is running stops it and discards its result; nothing is added to the new image.

  • The first search on an image takes longer: the detector features are computed once and then reused by every later search on that image.

  • At most 200 objects come back from one search, and a search name is cut at about 30 word pieces (the model's prompt limit), so keep it short.

  • Recent search names are remembered (the last 64), so searching the same name again is faster. Capital letters and extra spaces don't matter.

  • Cancel, then search again right away is fine: the new search starts once the step that was still running has finished.

  • Confidence labels — each object above the threshold is marked with its score, 0–100%, in a small dark label at the top-left corner of its box. The label keeps the same size at every zoom level and stays inside the visible part of the image while any part of the box is on screen. It follows the slider: an object the threshold drops loses its label, and one it brings back gets it again. Only the objects being kept are labelled, so the labels show you how high to raise the threshold, but not what a lower one would add. The score is the detector's own confidence, not a measured accuracy. Show confidence on masks, under the slider, turns the labels off and on; it is on again each time the app starts.

  • Display Options don't affect it. Contrast, Brightness and Background Darkness change only how the image looks; Find Objects always searches the original image.

  • Unused Classes rows have a sparkles button that searches for that class right away, without opening the search panel. It is disabled until the model has loaded and while another search or prediction is running.

Tip

Start it from the Find Objects with AI… button at the bottom of the Classes sidebar (disabled until the model has loaded), or press F (customizable). The shortcut is unavailable while the Image Browser, the Annotation Editor or a results preview is open, so a stray key press can't close or discard them, and also while an image is being analysed or a search is running (the sidebar button is greyed out then too). The sidebar button is not blocked by the open panels: using it closes the Annotation Editor (or discards a results preview) first.

Find Similar

When an object is hard to put into a name, show the detector one: Find Similar finds every object that looks like the examples you draw. It runs the same search and lands in the same results as a text search.

  1. Switch to Similar with the Text | Similar switch at the top of the Find Objects panel. While it is on, the image takes boxes: the live hover preview is paused and a click no longer starts a mask.

  2. Draw an example. Drag a box around one object; it is outlined in green. Add another example if the objects vary a lot. ⌥-drag instead to mark a not-example, outlined in red: something the search should not return. At least one example is needed, up to 10 boxes are kept, and a box only a few pixels across is ignored.

  3. Adjust a box by clicking its edge to select it. Drag the box to move it, drag a handle to resize it, press ⇄ to switch it between example and not-example, or press × or ⌫ to delete it. Clear removes every box.

  4. Press Find Similar (or Return). You can type a class name first. The results are the same as for a text search: the same threshold slider and confidence labels, Back, Save and undo. The boxes stay drawn on the image while you review them.

  • The class name is optional. With boxes alone, the detector gets only your examples, and Save asks you for the class. With a name, the name and the examples are used together, and Save offers that name.

  • Boxes belong to one image. They are dropped when you switch to another image. Back from the results keeps them, so you can adjust a box and search again; closing the panel with Esc, or discarding the results, clears them.

  • Switching back to Text hides the boxes, and a text search ignores them.

  • Not for a whole folder. Example boxes belong to one image, so Run on Whole Folder… is only offered in Text mode.

  • The same limits as a text search apply: at most 200 objects, the first search on an image takes longer, and Display Options don't affect it.

Tip

Draw the example box tight around one whole object. If the results include a wrong kind of object, try a ⌥-drag not-example around one of the mistakes and search again. If obvious objects are missing, lower the threshold or add an example of the kind that was missed.

Find Objects in Folder

Runs one search on every image of the open folder and saves what it finds, with no review step. Try the name on one image with Find Objects with AI first to choose a Confidence Threshold you trust, because the same threshold is applied to every image. In Free Mode this is a MaskLabel Pro feature.

  1. Start it from File ▸ Find Objects in Folder…, or press Run on Whole Folder… in the Find Objects panel, which brings the name you typed with it. Only a text search can run on a folder: example boxes belong to one image. It is disabled until the model has loaded, and while anything else is running: another SAM job, a folder scan, an image move between splits, or an export.

  2. Choose the name to find (it is also the class the objects are saved under), the Confidence threshold, whether to save as Pixels or Polygon (with the outline detail for polygons), and whether to leave alone images that already have the class or are marked empty.

  3. Start the search and let it run. The sheet shows the image being searched with its detections drawn in the class color (Pixels masks are merged into one overlay in that color) and their confidence (the single-image search above previews in the Hover Mask Color instead), the counts so far, and the lists of failed, skipped and saved-with-a-warning images. Cancel stops at the next step: the image being searched is thrown away and left unchanged, and images already done keep their new layers.

  • What is saved — one layer per object, as Pixels or Polygon masks according to the Save as choice, added to the image's existing layers. Existing layers are never changed. A new class is added only once something is found; an existing class keeps its color.

  • Left alone — an image that already has the class, or is marked empty, is counted as left alone; each has its own switch. A rerun therefore carries on where a cancelled run stopped, and doesn't add duplicates, and skips such images without opening the photo again (their annotation files are checked once, up front, in parallel), so a resumed run gets through them quickly. An image whose labels you cleared is not left alone: it is searched like any other.

  • Skipped — an image that is open with unsaved edits (or a save still in progress) is skipped, and if you edit the open image while it is being searched, its result is thrown away. Save it (⌘S) and run again.

  • Failed — an image that can't be read, or whose annotation file is unreadable or was made for a different image size, is listed with the reason and left unchanged. Copy all copies a list to the clipboard.

  • Saved, but check — the objects were saved, but the image's “marked empty / cleared” flag couldn't be removed (for example a read-only folder), so it may show as empty again after the folder is reopened. Nothing is lost.

  • At most 200 objects are kept per image, as in Find Objects with AI.

  • It takes time — roughly a second or more per image, longer for large photos or many objects. The app stays busy for the whole run.

  • Recent names and the options are remembered on this Mac.

Note

There is no single Undo for a whole run. The first time an image's annotation file is changed, the original is copied to a hidden .folder_find_backup folder inside the annotations folder; copy a file from there back to restore it. An image that gets objects no longer counts as marked empty or cleared. An image that had no annotation file before the run has no backup: to undo it, delete the new layers, or use Mark as Empty again. Your YOLO .txt label files are not changed — use Export to write the new objects out.

7. Display Options

  • Image sliders — Contrast, Brightness and Background Darkness change only how the image looks on screen (SAM and exports always use the original pixels). Useful for dim images like fluorescence microscopy. The panel stays open while you click, zoom and pan the image, so you can adjust and segment without closing it.

  • Contrast — stretches the image around its own average brightness, so a dim image keeps its black background and a mid-gray image keeps its overall tone while objects and background move apart.

    It is most useful on gray, low-contrast images (for dim fluorescence, Brightness is the tool to reach for). The average is taken after Brightness is applied, so the two sliders work together.

    It only goes up from zero (lowering contrast is not offered, because it would grey the black background), and because the average stays put, even the top of the slider will not blow the image out.

  • Brightness — has a much wider range than Contrast, because very dim images need a large boost before they become clickable. It multiplies the pixel values instead of adding to them, so a black background stays black. Positive values brighten (the right end of the slider is a very strong boost); negative values darken, down to black.

  • Background Darkness — dims everything outside your masks (hidden masks don't count), so it needs at least one mask to be useful; with no masks it darkens the whole image evenly.

  • Order and persistence — the three are applied in a fixed order: Brightness, then Contrast, then Background Darkness last, so a Darkness of 0.5 dims the background to half of what you see after Brightness and Contrast, however bright you made the image. These settings are not reset when you open another image, so one dial-in carries across a folder of similar images; Reset (the circular arrow next to Image) puts them back.

  • Large images — while you drag one of these three sliders on a very large image, the preview is drawn at reduced resolution so it keeps up, and it sharpens as soon as you let go (Actual Size is briefly inexact during the drag). Only images above about 20 megapixels are reduced; smaller ones are redrawn at full resolution while you drag.

  • Value readouts — each slider shows its current value on the right of its name (Mask Opacity as a percentage). The circular arrows reset a whole section.

  • Image reset (circular arrow next to Image) — puts only Contrast, Brightness and Background Darkness back to their defaults, leaving the mask settings alone. Grayed out until one of the three has changed.

  • Masks reset (circular arrow next to Masks) — puts only Mask Opacity (back to the default fill opacity) and Mask Visibility (back to Full) back, leaving the image sliders and the switches (including Pixels Mask Stroke) alone. Grayed out until one of them has changed.

  • Mask Opacity — sets how opaque masks are drawn (0 = invisible, 1 = fully opaque). It also sets the opacity of the live preview you see before a click, and while you drag a box for a new mask, so the preview looks like the mask you get. Remembered between launches. Reset (next to Masks) returns it to the default fill opacity, not to fully opaque, and that default is what is remembered afterwards.

  • Mask Visibility (Full / Half / Hidden) — scales how opaque every mask (and the new-mask live preview) is drawn, relative to the Mask Opacity you set: Full is that value, Half is half of it, Hidden is zero. The Cycle Mask Visibility shortcut (default H) cycles Full → Half → Hidden → Full. It only changes how masks are drawn, so the Layers table's eye icons and mask selection are untouched, and the setting carries over to other images. Reset (next to Masks) returns it to Full.

  • Behavior — the controls below (Hide Mask Hover, the Hover Mask Color swatch and Open Editor on Layer Click) sit under their own Behavior heading. They are settings rather than image adjustments, so they have no reset arrow and the Image and Masks resets leave them alone. When the window is too short to show every control, the controls scroll and the title stays in place.

  • Hide Mask Hover — temporarily turns off the live hover preview (shortcut, default V). Turning it off again shows the preview at the pointer straight away, without moving the mouse. Note that while it is on, clicking empty canvas or dragging a box does not start a new mask (see Segmenting an Object).

  • Pixels Mask Stroke — (under Masks, below Mask Visibility; no reset arrow) draws an outline around Pixels-mode masks so they stay readable against a similar-toned background (shortcut, default S). On by default and remembered between launches; turning it off or on also changes how already-committed Pixels masks are drawn. When you edit a Pixels mask on a very large image, the new fill appears first and the outline follows a moment later; turning the outline off removes that wait.

  • Open Editor on Layer Click — the on-screen twin of the E shortcut. On by default: clicking a saved mask or its Layers row opens the Annotation Editor. Switch it off to just select the mask and edit its pixels or polygon points. Class rows still open the editor. It switches back on when you restart the app.

  • Hover Mask Color — the swatch sets the color of the live preview that follows the cursor before your first click (its opacity follows Mask Opacity). It doesn't change committed masks. It is one color for the whole app, remembered between launches, so it stays the same when you open another folder. Until you pick one it is the default cyan.

What is remembered

Some of these controls are kept the next time you start the app, others deliberately start fresh. Viewing toggles are not kept, so a forgotten switch can't make the app look broken after a restart. Where Settings Are Stored lists every setting and where it is kept.

  • Remembered between launches, on this Mac — Mask Opacity, Hover Mask Color, Pixels Mask Stroke, and the Polygon / Pixels mode and Simplify level in Mask Options. They are stored in the app's preferences file. File ▸ Export Settings… (or Customize Shortcuts ▸ Export…) saves them to the settings file and Import Settings… restores them.

  • Start fresh every launch — Contrast, Brightness, Background Darkness, Mask Visibility (Full / Half / Hidden), Hide Mask Hover and Open Editor on Layer Click. Nothing is stored for them — not in the preferences file, the settings file or the dataset.

Note

These never touch the actual pixels SAM3 segments, so pushing them up to see something faint can't skew a prediction.

Tip

The default shortcut D (or the toolbar button) opens and closes this panel; clicking the image, sidebar or toolbar leaves it open. It only affects the canvas image, so it closes (and the shortcut does nothing) while the Image Browser is open. Opening Customize Shortcuts closes it too: the two panels share the same corner, so only one shows at a time. In a short window the options scroll under the header, so none of them is ever cut off.

8. Refine Boxes with SAM

File ▸ Refine Boxes with SAM… turns the plain rectangle annotations in the whole folder (typically from a YOLO detection import) into editable polygons. Each box is given to SAM as a prompt, and the mask it returns is traced into polygons. If the mask has several separate pieces, each piece becomes its own layer. In Free Mode this is a MaskLabel Pro feature.

  • Scan first — the sheet counts how many boxes in how many images will change. Imported polygons and masks are never touched.

  • Outline detail — Simple, Balanced or Detailed, the same trade-off as the Simplify slider in Polygon vs. Pixels. It is the very same setting as that slider: change it here, in Find Objects in Folder or in Mask Options and the others follow, and the Layers-table buttons use it too.

  • Options below Outline detail — Skip boxes smaller than leaves very small boxes as rectangles (measured in SAM's own input size, so it behaves the same on small and large photos); a minimum confidence, the margin sampled around the box, and an optional center click are also available. The defaults are 20 for the minimum size, 0.25 for the confidence, 25% for the margin and the center click off; they suit most datasets and are remembered between runs.

  • Tiny boxes cost nothing — an image whose boxes are all below the minimum size is passed over without running SAM on it. Boxes that were kept as rectangles are tried again on every run, so an image with only such boxes still takes the full pass unless you raise the limits.

  • Boxes SAM can't segment convincingly keep their rectangle. The polygons made counter counts polygons, not boxes: a box whose mask splits into several pieces adds several, so it can be higher than the number of boxes converted.

  • Refined images and re-import — an image that was refined is no longer regenerated from its YOLO .txt file by the raw-pixels re-import switch, so the refinement is not wiped. Restore the backup from .box_refine_backup if you want the original rectangles back.

  • When the Layers-table buttons refuse — a box is left alone, with a notice, if SAM is still analysing or busy with another task, or if the layer's size doesn't match the image SAM analysed (reopen the image).

  • Objects with a hole (rings, donuts) become their outer outline — a polygon cannot have a hole. The optional center click adds a positive click in the middle of the box: it helps compact objects, but on a ring or crescent that point can land on the empty centre, so leave it off for those.

  • Which pieces become layers — only pieces that lie mostly inside the box are kept, tiny fragments next to the main piece are dropped, and a mask that covers under 5% of the box is rejected (the rectangle stays).

  • Just this image — press the sparkles button on a rectangle's row in the Layers table to convert that one box, or Convert Boxes with AI under the table (shortcut A, customizable) to convert every rectangle on the current image at once (one ⌘Z undoes all of it). Both use the same Advanced settings as this sheet. While several boxes are converting, a Cancel button appears in the toolbar; boxes already converted stay, the rest keep their rectangle. A box you move or resize while SAM is working is left as you edited it, with a notice.

  • Dragging a box for a new mask uses the Skip boxes smaller than setting too: a drag shorter than that counts as a plain click (see Segmenting an Object).

  • Cancel any time — Cancel stops after the group of boxes SAM is working on (at most 16), not after the whole image. If it is pressed while an image's features are being extracted, that step finishes first. Images already finished stay refined; boxes that never ran keep their rectangle and are not counted as "kept", so after a Cancel the Kept as rectangles because… list can add up to fewer than the boxes in the folder.

  • While it runs the rest of the app is paused: menus and shortcuts that start SAM are disabled until it finishes or is cancelled.

  • If Start does nothing — when SAM is still busy or loading, or another folder operation (a scan, an image move or an export) is running, an orange line under the options says so. Wait for it to finish, then press Start again.

  • The image that's open — if it has unsaved edits (or a save of it is still in progress) it is skipped: it is counted under skipped and listed under the counters with the reason until you close the sheet. Save it (⌘S) and run Refine Boxes again to include it. The same happens if you edit that image while it is being refined: the refinement is discarded instead of overwriting your edit. If it was refined and has no unsaved edits it is reloaded automatically.

  • Images that can't be refined — an unreadable image, one whose saved annotations can't be read (missing or damaged), one whose size no longer matches its annotations (for example the photo was replaced), one whose backup can't be written, or one whose annotations changed on disk while SAM was working on it, is left unchanged and counted under images failed.

    Each one is listed under the counters with a plain-language reason (for example, that the image couldn't be read), and the list stays until you close the sheet.

    Only the first 20 failed and 20 skipped images are shown; Copy all puts the complete list on the clipboard. To retry, close the sheet and run Refine Boxes again — finished images are not repeated.

  • Preview and time left — the sheet shows the latest image with each box (orange dashed) and the polygon SAM made from it, filled in that box's class color (green if the class color can't be read). The time estimate appears after two images and counts only images SAM actually ran on; images passed over because every box was too small are not counted.

  • On the Done screen, Kept as rectangles because… counts the boxes SAM left alone by reason (box too small, SAM confidence too low, mask covering under 5% of the box, mask filling the whole area around the box, SAM found nothing, and so on). Convert Boxes with AI groups its "kept as rectangle" notice the same way and names the most common reason.

Note

Your YOLO .txt label files are not changed. The previous annotation of each refined image is backed up to a hidden .box_refine_backup folder before it is replaced. Use Export to YOLO afterwards to write the new polygons — the exported label files then contain polygon (segmentation) lines instead of boxes. To undo an image, copy its file from .box_refine_backup back over the file with the same name in the annotations folder; the backup holds the first version only, so later refinements of the same image do not overwrite it.

Tip

SAM analyses every image once, which is the slow part — roughly a second or more per image, longer for large photos. All boxes in one image share that pass. For a single box, use the sparkles button on its row in the Layers table instead.

9. Saving to Disk

Save Annotations (⌘S) writes the current image's masks and class assignments to the annotations folder. By default that is an “annotations” folder inside the folder you opened; change it with File ▸ Change Annotations Folder. Saving happens in the background, so large images don't freeze the app, and several saves in a row are written in the order you made them.

You don't have to press Save after every image: the open image is also saved automatically when you go to another image, open the Image Browser, open or close a folder, change the annotations folder, or quit. If you delete every mask on an image and save, its saved annotations are removed. If a save fails (for example the folder is read-only, missing or the disk is full), a red “Annotations not saved” message appears over the image; your edits stay in the app and are tried again on the next save, so fix the problem and press ⌘S again.

If you quit while an image still has edits that couldn't be saved, the app asks whether to quit anyway. The first time you save a single loose image (opened without a folder), the app asks where to keep its annotations and remembers the choice for images from the same folder.

Change Annotations Folder (⌥⌘O, File menu, or the folder button in the toolbar) lets you choose a different folder to read and write annotations in. The choice is remembered for that dataset folder, and it also works for a single loose image. Annotations already saved are not moved or copied, so switching back to the old folder finds them again.

The image on screen is saved to the old folder first, and only once that has finished is it reloaded from the new one; if that save fails, the folder is not changed and you are told why, so no edits are lost. The classes found in the new folder are added to your class list. Choosing the folder that is already in use does nothing, for a single loose image as well. A loose image with unsaved masks that has never been saved anywhere keeps its masks on screen and they go to the new folder on your next save.

Tip

The Image Browser's Annotated / Unannotated / Empty chips and per-thumbnail overlays track what's been saved across the whole folder, so it's easy to see what's left (Image Browser).

10. Roboflow / Ultralytics (YOLO) Round Trip

Label a Roboflow or Ultralytics dataset in MaskLabel, then write it back out. COCO datasets work too (see Import COCO and Export COCO below).

Import YOLO

  1. Export the dataset from Roboflow in YOLO format.

  2. Drag the exported parent folder (the one containing data.yaml and the train/valid/test folders) onto the window. File ▸ Open… and File ▸ Import YOLO Dataset… do the same thing.

An Ultralytics-style dataset — images/train, images/val, images/test with a matching labels/ folder and a dataset-named YAML (coco8.yaml, carparts-seg.yaml, …) instead of data.yaml — is recognized the same way and imports just as automatically. A flat dataset — just images/ and labels/ directly in the parent folder, with no train/valid/test folders — also imports, as a single Train split.

What import does

  • Class names are read from the dataset's YAML (an inline/block names: list, or Ultralytics' own {index: name} dict).

  • Every label file is imported as editable polygons, and each image's train/valid/test split is remembered.

  • Your images stay where they are — nothing is moved or copied.

  • Background images — an image whose label file is empty (zero bytes) is marked Empty on import, so it counts as a background example, not as Unannotated. An image with no label file at all stays Unannotated. Images that already have annotations here, or whose imported labels you removed, are left alone.

  • Lines that can't be read — a label line is skipped, and counted in the import warning, when it is not a box or polygon (keypoints, an odd number of polygon values), has a negative class, or contains a value that isn't a finite number (nan, inf). Label files are read as UTF-8; UTF-16 (with a byte-order mark) and Latin-1 files are read too. A box line has 4 numbers after the class, a polygon line 6 or more (an even count), and an oriented-box line (8 numbers) is imported as a 4-point polygon.

  • In the Image Browser, the Train / Valid / Test chips filter by split and combine with the Annotated / Unannotated chips.

Import Ultralytics NDJSON

Choose File ▸ Import Ultralytics NDJSON… (or drop the .ndjson file onto the window) and pick the .ndjson downloaded from the Ultralytics Platform dataset page. The file holds the labels and a download link for each image, but no pictures, so MaskLabel downloads the images first and then imports the result like any other YOLO dataset.

  1. Choose the .ndjson file, then choose where to create the dataset folder. A folder named after the file is created there with data.yaml, images/ and labels/ for train, val and test.

  2. Wait for the downloads. The status line shows how many images are done, the speed and the time left. Large sets (for example 100,000 images) take a while; the speed adjusts itself to your connection. Cancel stops it.

  3. The folder opens by itself once the downloads finish, with the Image Browser showing the imported labels.

  • Labels — boxes, segments and oriented boxes become editable polygons. An image with no annotations is marked Empty (a background example). The file's task decides what is read: segment → polygons, detect → boxes, obb → oriented boxes. Pose / keypoint rows can't be imported and are skipped, and a classification dataset (task classify) has nothing to annotate, so it is refused with a message.

  • Big datasets — a set like COCO 2017 with about 100,000 images is tens of GB. Check the free space first (the size is in the file), expect the downloads to take a long time, and then a few more minutes while the labels are imported after the last image arrives.

  • Names and splits — the folder is named after the .ndjson file, so renaming the file creates a different folder. val / valid / validation become val, an unknown or missing split goes to train, and two images with the same name in one split get _2, _3, … added.

  • Safe to run again — images already in the folder are skipped (and so are their label files), so a cancelled or interrupted import continues where it stopped, and importing a finished dataset again is quick. Importing again after a failure retries only the missing images.

  • Expired links — the image links in the file stop working about a week after it was exported. If about 24 downloads in a row come back expired, the import stops and says so (this also works when you resume a partly downloaded set): download a fresh .ndjson from the Platform and import it into the same folder; images already on disk are not downloaded again.

  • Connection problems — if about 150 downloads in a row fail (for example you went offline), the import stops early instead of retrying every remaining image. Check your connection and import the same file into the same folder again.

  • Leftover .part files — a file ending in .part inside images/ is an interrupted download; it is safe to delete, and the next import fetches that image again.

  • Failures list — images that could not be downloaded are listed in the alert and in import_report.tsv inside the dataset folder, with their line number in the .ndjson and their link.

  • Disk space — before a new import, MaskLabel checks that the disk has room for the size stated in the file, and stops if it runs out of space.

  • Problems with the file — if the file isn't an Ultralytics dataset .ndjson, has no images, or the folder can't be created or has too little room, an alert says why and nothing is downloaded.

Note

Only the labels you downloaded are imported. A label file that already exists is not rewritten; to refresh labels from a newer .ndjson, delete the labels folder (not the images) first. Annotations you have already edited in MaskLabel are never overwritten.

Export YOLO (back to Roboflow)

File ▸ Export to YOLO… writes your annotations back into each split's labels folder and updates data.yaml (existing class numbers never change), so you can zip the folder and upload it to Roboflow again.

  • Polygon layers are exported as edited.

  • Pixels masks are converted to polygons using the Polygon mode's Complex setting.

  • COCO crowd regions are skipped. A Pixels mask imported from a COCO crowd region (iscrowd 1) covers a whole group of objects, and YOLO has no crowd or ignore concept — written out, it would train as one big object.

    These layers are left out of every YOLO export, and the Export Complete panel and the export log say how many were skipped. Your annotations are not changed, and Export COCO still writes them back as crowd regions.

    If a crowd region is all that is left on an image, that image's label file is removed from the export (an empty label means "no objects"), so deleted objects never linger in an old file.

  • Background images — an image you marked as empty gets a zero-byte label file, so it counts as a background example. An image that is unannotated and not marked empty gets no label file at all, and neither does an image whose only objects were skipped (such as crowd regions). If a label file can't be written, the export log says so.

  • Images are not copied.

Note

Before the first export, the original label files and data.yaml are saved to an original_labels_backup folder, and that backup is never overwritten.

Classes already in data.yaml keep their numbers, even if no mask uses them any more, so existing label files, other splits and training configs stay valid.

New classes you created and used are added at the end, in alphabetical order, whichever image is open when you export. If you rename a class that came from data.yaml, the old name stays at its number and the new name is added at the end.

Removing an unused class from the sidebar does not remove it from data.yaml.

Import COCO

Choose File ▸ Import COCO Dataset… (or drop the parent folder). Always choose the parent folder that contains the split image folders.

  • Roboflow COCO — train/valid/test folders, each holding its images and _annotations.coco.json.

  • Official COCO (cocodataset.org) — train2017/val2017/test2017 image folders, with instances_<split>.json either inside each folder or in an annotations folder next to them.

An untouched official download looks like this:

my_coco/
├── train2017/   (images only)
├── val2017/     (images only)
└── annotations/
     ├── instances_train2017.json
     └── instances_val2017.json
Note

Choose my_coco — not annotations and not an image folder. You don't need to move the JSON files.

How annotations are found and converted

For each split, MaskLabel looks for its annotations in this order:

  1. _annotations.coco.json inside the split folder

  2. instances_<split>.json inside the split folder

  3. annotations/instances_<split>.json beside it

  • test2017 has no annotation file, so its images are only tagged Test.

  • Background images — in a split whose annotation file has annotations, an image that is listed in the file but has none is marked Empty (a background example). Images that already have annotations here, or whose imported labels you removed, are left alone.

  • Polygons and boxes become editable polygon layers; RLE masks (including crowd regions) become Pixels masks — both the compressed string form (pycocotools) and the plain list of run lengths are read.

    An RLE mask is skipped, with a warning in the import log, when its size matches neither the upright photo nor (for sideways EXIF photos) the stored picture, when its run lengths are corrupt, or when it is larger than about 150 megapixels.

    Image size in the file — polygons and boxes are relative to the width and height the JSON states for the image. If the pictures on disk have a different size but the same shape (for example they were resized after the export), the coordinates are scaled to the real size and the import log says how many images were affected. If the shape differs too, the coordinates are imported as written and the log warns that they may be misplaced.

    A polygon annotation with several parts becomes one layer per part, so the instance count can be higher than the number of annotations in the file.

    A polygon annotation marked as a crowd region (iscrowd 1) becomes one Pixels mask covering all its parts and stays a crowd region. If that single mask can't be built (an empty polygon, or an image larger than about 150 megapixels), its parts are imported as ordinary polygon layers instead and the import log says so.

  • Each image's train/valid/test tag is saved in MaskLabel's own format (dataset_splits.json and the image's annotation file). Change a tag by pressing Edit Split in the Image Browser, selecting images, then right-click ▸ Move to Train/Valid/Test; File ▸ Export to YOLO… then builds a new YOLO dataset using those tags.

  • Large annotation files such as instances_train2017.json (about 450 MB) are read in a streaming fashion, so importing takes roughly 1 GB less memory and a few seconds instead of about 20.

Export COCO

File ▸ Export COCO… opens the same panel as Export to YOLO.

  • Plain folder — writes a new Roboflow-layout COCO dataset (train, valid and test folders, each with its images and an _annotations.coco.json) using the split ratio, shuffle, limit and empty-image options. Nothing existing is changed.

  • Folder that is itself a COCO dataset — “Use existing split ratio” exports in place: a fresh _annotations.coco.json is written into each split folder, images are not copied, and the previous files are saved once to original_annotations_backup.

  • Resize images — downscales larger images (annotations are scaled to match); other images are copied unchanged.

  • Rotated photos — a photo with an EXIF rotation or flip is always re-saved upright (tag removed), with or without Resize, so every coordinate matches the file next to it. See Rotated photos (EXIF).

Press Export to see progress; Cancel Export stops it (an in-place export then changes nothing). When finished, an export summary with image and class counts is shown unless you turn it off. Only classes actually used are listed.

In-place export: which JSON file is written

  • Roboflow layout — each split's _annotations.coco.json is replaced by the new file with the same name. The original is first copied once to original_annotations_backup/<split>/ (unless you turn the backup off), and an existing backup is never overwritten.

  • Official COCO layout (instances_<split>.json) — the original file is never modified. A new _annotations.coco.json is written next to the images, and from then on that folder is read from it, because it takes priority over instances_<split>.json. The export summary names each split where this happened.

  • The new files are built as hidden temporary files and swapped in only after every split is ready, so Cancel — or a failure while building — leaves everything as it was. If the backup can't be completed, nothing is changed.

  • A split that has no annotation file and nothing annotated or marked empty (for example the official test2017) gets no file.

  • Unannotated images — an image that is neither annotated nor marked empty is left out of the new file, and the export log warns about it. Listing it with no annotations would turn it into a background example. Mark it empty (M) first if that is what it is.

Masks and training frameworks

  • Each layer becomes one annotation; polygons are exported as edited.

  • If an annotated image ends up with no exportable annotation at all (for example its mask file can't be read), it is still listed in the file without annotations — which readers treat as a background image — and the export warnings name it.

  • “Convert pixel masks to polygons” (on by default) traces pixel masks into polygons, which RF-DETR, Detectron2 and Ultralytics’ COCO converter all read (holes are not kept, the outline is approximate, and very small pieces, roughly under 3×3 pixels, are left out; a mask with more than 500 separate pieces keeps the 500 largest). Turn it off to keep exact masks as RLE (iscrowd 0). Export always writes the compressed string form (what pycocotools produces); the plain list form is read on import but never written.

  • The box only affects Pixels masks: polygon layers are always exported as polygons, and crowd regions imported from a COCO file (iscrowd 1) always stay RLE with iscrowd 1.

  • RF-DETR reads RLE directly, Detectron2 needs INPUT.MASK_FORMAT: bitmask, and Ultralytics’ COCO converter only reads polygons — use Export to YOLO for YOLO training.

Rotated photos (EXIF)

Phone and camera photos are often stored sideways or upside-down, with an EXIF tag that tells viewers how to turn them. MaskLabel always shows and labels the photo the right way up (upright): the canvas, SAM and every saved label use that picture.

The short version

  • To share a dataset or train on it, use Export to a new folder (YOLO or COCO). Rotated photos are saved upright with the EXIF tag removed, and the labels match them. Importing that folder again needs no switch.

  • When you import labels from another tool, MaskLabel assumes they match the upright photo. If they look turned or misplaced, a banner appears: switch on Labels were drawn without EXIF rotation (that tool showed the photos rotated and the labels were drawn that way).

  • Export in place only rewrites the label files; your images are never changed and keep their EXIF tag. Read “Exporting in place, then importing again” below before deleting the annotations folder.

What each export does

  • Export to YOLO — a rotated photo is re-saved upright (tag removed), so the labels match. If a photo can't be re-saved in its own format (for example WebP or HEIC on a Mac that can't write it), it is saved as a lossless PNG with a .png name instead; only if that also fails is it skipped with a warning rather than exported with rotated labels.

  • Export COCO (new folder) — same rule: rotated photos are re-saved upright and the JSON is written for those pixels. Re-importing your own export is exact for every tag. Only photos that are rotated or resized are re-encoded, in their own format (JPEG, HEIC and WebP at high quality; PNG, TIFF and the like losslessly, keeping 16-bit when possible). Every other image is a byte-for-byte copy. A re-encoded copy keeps its Exif, GPS location, IPTC and colour profile (only the rotation tag is reset), so remove location data before sharing a dataset publicly.

  • Image formats — JPEG, PNG, GIF, BMP, TIFF, HEIC/HEIF and WebP are opened.

  • Export in place, YOLO — labels are written the same way you imported them: with the switch on, for the stored (un-rotated) picture; with the switch off, for the upright picture.

  • Export in place, COCO — the same rule as YOLO: labels are written the way you imported them. With the switch on, or when the JSON you imported gave sideways photos (EXIF 5–8) at their stored size, the JSON is written for the stored (un-rotated) picture with the stored width and height; otherwise it is written for the upright picture with the upright width and height. The choice is per dataset, not per photo. A folder that was never imported from COCO is written for the stored picture. Image files are never changed, and the previous files are kept in original_annotations_backup.

  • 16-bit images — rotating or resizing keeps the bit depth when the system can do it for that pixel format. When it can't, the picture is processed as 8-bit and a note is written to the system log (Console app).

  • Copy to Another Folder — the image file is copied as it is (its EXIF tag stays). An image marked as empty is copied with its mark (into a YOLO dataset it also gets an empty label file). Into a YOLO dataset the label file is written the way that dataset is set up: for the stored picture if its switch is on, otherwise for the upright picture.

Exporting in place, then importing again

The switch Labels were drawn without EXIF rotation is saved inside the annotations folder, next to your labels. If you delete that folder, the labels and the switch are both forgotten, and the next import starts with the switch off.

Deleted the annotations folder? Drop the dataset folder on the window again (or use File ▸ Import YOLO Dataset…). It imports again and recreates the folder — also when that folder is already open, which is what you get after relaunching (the app reopens the last folder without importing).

  • YOLO — a YOLO file does not say which picture it was made for, so after the re-import every rotated photo is read as upright. If the labels were written for the stored picture (switch was on), they look misplaced and the banner appears: switch it on again.

  • COCO — the JSON states the image size, so sideways photos (EXIF 5–8) line up by themselves. If an image has no width and height in the JSON, the size of its first RLE mask is used instead. If it has neither, its polygons and boxes are assumed to match the upright photo. Upside-down and mirrored photos (EXIF 2, 3, 4), and square photos with a sideways tag (EXIF 5–8), have the same size either way, so the banner appears for them: switch it on if their labels look misplaced.

  • Not sure which to choose? Look at the photo and its labels. If the labels look turned or mirrored compared with the objects, switch it on. You can switch it back and forth any time; images you have edited by hand are never changed by the switch.

  • Avoid the question: export to a new folder instead (see above).

Labels that look rotated after import

  • YOLO — if the labeling tool ignored the EXIF tag (it showed the photos rotated and the labels were drawn that way), a banner appears after import with Labels were drawn without EXIF rotation. Turn it on and the labels of the rotated photos are re-read from the untouched .txt files and turned to match the upright photo. Images you have already edited (or imported by an older version) are left as they are.

  • YOLO, sideways photos (EXIF 5–8) — a YOLO file stores fractions of the picture, not pixels, so MaskLabel cannot tell which picture the labels were made for. The banner therefore appears for every rotated photo, sideways ones included: look at the photo and its labels, and switch it on if they look turned.

  • COCO — sideways photos whose JSON size equals the stored size are detected automatically. Upside-down or mirrored photos (2, 3, 4), and square photos with a sideways tag (5–8), have the same size either way, so a banner with the same Labels were drawn without EXIF rotation switch appears for them: turn it on if their labels look turned or misplaced. (Applies to a dataset imported with this version; clear the annotations folder and re-import an older one.)

  • COCO masks (RLE) — each RLE mask decides by its own size: equal to the upright size it is used as is, equal to the stored size of a sideways photo (EXIF 5–8) it is turned to match; any other size is skipped with a warning. Boxes without a segmentation are imported as boxes.

  • YOLO lines — a line with exactly four numbers after the class is always read as a box (cx cy w h), so a polygon with only two points cannot be imported. Polygons need at least three points (six numbers).

  • Annotations not loaded — if an image's saved annotations have a different size than the picture (typically width and height swapped), they are not drawn, and a banner says so. They are kept on disk until you choose Discard old annotations.

11. Exporting a Plain Folder to YOLO

If you labeled a normal folder of images (not an imported Roboflow export), File ▸ Export to YOLO… opens a split sheet.

  1. Set the ratio. Drag the two handles on the bar (Train / Valid / Test always add up to 100%), type exact percentages, or pick a preset.

  2. Choose options (below).

  3. Press Export. A new folder is created with train/valid/test images and labels plus data.yaml, ready to zip for Roboflow.

Options

  • Shuffle — randomizes which images land where; the seed makes it repeatable.

  • Include empty (background) images — adds images you marked as empty (M) as background examples.

  • Limit number of images — exports only a subset: the first images in thumbnail order, or a random sample when Shuffle is on.

  • Resize images — downscales larger images to a maximum dimension you set, preserving aspect ratio, to save training time and disk space. Labels stay correct without any adjustment.

Note

Classes are always balanced across the splits automatically, so rare ones aren't left out of Valid or Test. There's no option to turn this off.

Note

The new data.yaml lists only the classes used by the exported images, in alphabetical order, numbered from 0. Unused classes are left out, so these numbers can differ from the original dataset or from an export that includes different images; always train with the data.yaml that was written next to the labels.

If two exported images in the same split share a name (for example a.jpg from two folders), the later ones get _2, _3 added (a_2.jpg) and you are told which were renamed; the same name in different splits is kept as is.

In-place export is the opposite: it keeps every class already in data.yaml at its original number.

Note

Masks imported from a COCO crowd region (iscrowd 1) are not written to YOLO labels — YOLO has no crowd concept, and one mask over a group would train as a single object. The Export Complete panel and the export log say how many were skipped.

Exporting again

If some images already have a split from an earlier export, a dropdown at the top of the sheet lets you choose:

  • Use existing split ratio — those images keep their split and only new images are assigned.

  • Change split ratio — everything is re-split from scratch using the percentages you set.

Tip

Want just some of the images? In the Image Browser, turn on a filter (annotated, split, class, or filename) and press Export N images… — pick YOLO or COCO, and only the matching images are exported. “Limit number of images” can then sample that down.

Tip

Images are copied — instantly and without extra disk space on the same APFS volume. The chosen splits are also saved back into your annotations, so the Image Browser's Train / Valid / Test chips work on the source folder.

12. Copying Images to Another Folder

Use this to pull a smaller dataset out of a big one — for example only the images that contain one class, only a split, or only the ones you've finished annotating. The selected images are copied together with their annotations, so the new folder can be opened, edited or trained from on its own. Nothing in the source folder changes.

  1. Filter the thumbnails in the Image Browser (Annotated / Unannotated, Train / Valid / Test, class, or filename) so only the images you want are showing.

  2. Press Edit Split, then select images by clicking them, or press ⌘A to select everything currently visible. Because ⌘A only selects what the filters show, this is the quickest way to take a filtered set.

  3. Press Copy to Another Folder… next to the “N selected” badge.

  4. Pick the destination from your recent folders, or use Choose Other Folder…. The sheet says whether it's a plain folder or a YOLO dataset and where the annotations will go.

  5. Choose how Train / Valid / Test is handled (below), then press Copy N Images.

Train / Valid / Test

  • Keep each image's current split — images keep the split they have now. Images without one go to the split you choose (or “No split” for a plain folder).

  • Put all of them in — every selected image goes to one split.

  • Random split by ratio — a repeatable random assignment using the percentages you set.

What gets copied

  • The image files, plus each image's annotation file and its pixel-mask files. Mask layers, polygons and COCO crowd regions (iscrowd 1) are all kept as they are.

  • Images marked as empty — an image you marked empty has no annotation file, only the mark, and the mark is copied with it, so it is still Empty (not Unannotated) in the destination. Into a YOLO dataset it also gets an empty label file, so it counts as a background image there. The result panel says how many were marked empty.

  • Plain folder destination — images go into the folder itself, and their splits are recorded in dataset_splits.json in its annotations folder.

  • YOLO dataset destination — each image goes into its split's images folder, and a matching labels file is also written so you can train from the folder directly. Classes the destination's data.yaml doesn't list yet are added to it; existing class numbers never change. A split folder that doesn't exist is created for the standard layouts.

  • Same name in different splits — copying train/dup_001.jpg and valid/dup_001.jpg into a YOLO dataset keeps both: each gets its own annotation file (train__dup_001.json, valid__dup_001.json). Into a plain folder only the first is copied, because both would be the same file there.

  • Nothing is overwritten. An image or annotation file whose name already exists in the destination is skipped and counted in the result. If a copy fails part-way, that image's partly copied files are removed so it can be retried.

Note

Copying is not exporting: the destination keeps your editable annotations (polygons and pixel masks). Use Export to YOLO or Export COCO when you want a training-ready dataset built from the whole folder.

Tip

Combine the two: copy a filtered subset into a new folder, open that folder, and export it — a quick way to make a small test dataset from a large one.

Note

The same selection can also be deleted: Delete… (after Mark as Empty and Copy to Another Folder…) moves the selected images and their annotations to the Trash. See The Image Browser.

13. The Image Browser

The Image Browser is the thumbnail grid of every image in the open folder. Click a thumbnail to open it. Thumbnails show a small overlay of each image's saved masks, so you can see what has been labeled without opening it. Hover a thumbnail to see its size in pixels (for example 4000 × 3000 px) — handy for spotting images of a different resolution in a folder; the size is the same upright pixel size shown next to the name in the title bar.

Filtering

  • Annotated / Unannotated — images with or without saved annotations.

  • Empty — images you reviewed and marked as having no objects. They are not counted as Unannotated. Mark one with the Mark as Empty button beside Clear All Masks (it reads “Empty ✓” once marked) or M while it is open — both work even while SAM is still analysing the image — or use Edit Split and right-click ▸ Mark as Empty (images that already have masks are skipped).

    The button and M only work on an image with no masks (clear them first), and pressing again removes the mark. It is unavailable while the Image Browser is open, because the open image is hidden behind it; select images with Edit Split and use its Mark as Empty button instead.

    Marks are saved immediately, without ⌘S, and a mark is removed automatically when you later save a mask on that image. If a mark can't be written (for example the annotations folder is read-only), a message tells you.

  • Pixels mask — images that have at least one Pixels-mode mask.

  • Train / Valid / Test — the image's split.

  • Class — type a class name and pick it from the list (↑ / ↓ to move, Return to choose, Esc to close).

  • Filename — matches any part of the file name, including the extension (so “.png” matches every PNG). Case and full-width / half-width differences are ignored, but accents are not (“e” doesn't match “é”). It isn't a pattern: spaces count and there are no wildcards. The grid updates a moment after you stop typing.

All filters combine: an image must pass every one that is active. The chip counts narrow to match the other filters, except Pixels mask, which always counts the whole dataset. Filters are remembered for each folder, including after you quit and reopen the app, and opening a different folder starts with all of them cleared.

Edit Split

Press Edit Split to select images instead of opening them. Click to select or deselect; the Select All button or ⌘A adds everything the filters currently show (after typing in the filename box, click an image or press Return first — otherwise ⌘A selects the text in the box; the button always works); ⌘⇧A or Esc clears the selection. With images selected you can:

  • right-click ▸ Move to Train/Valid/Test — change their split. In an imported YOLO dataset this moves each image file and its label into that split's folder on disk; in a plain folder it only changes the image's split tag.

    Right-click only offers this while Edit Split is on, and it is unavailable while an import, scan, count, delete or label re-import is running.

    Right-clicking an image that isn't selected also offers Move This Image Only. An image is never overwritten: if the target split already has a file with the same name, that image is left where it is and you are told why.

  • Mark as Empty (button next to Delete…) or right-click ▸ Mark as Empty / Remove Empty Mark — images that already have masks, and the open image if it has unsaved masks, are skipped; you are told how many. Images that couldn't be written to the annotations folder are reported separately from those skipped because they have masks.

    Right-clicking an image that isn't selected while a selection exists (for example because the filters hide it) offers both the whole selection and This Image Only, the same as Move. The items are left out while a scan, another empty-mark change, a move, a delete or a label re-import is running.

  • Copy to Another Folder… — see Copying Images to Another Folder.

  • Delete… — moves the selected images to the Trash together with their annotations and, for an imported YOLO dataset, their label files. You are asked to confirm first.

    While it runs, a card over the grid shows “Moving N of M images to the Trash…” with a Cancel button (images already in the Trash stay there), and the buttons are replaced by a “Deleting…” indicator.

    Any image that can't be moved to the Trash stays in the folder and stays selected, and you are told how many. Edit Split stays on after a delete.

    The one exception is an image whose name is shared with another image that is not deleted (the same name in two splits, or a.jpg next to a.png): the folder is then re-read and Edit Split ends.

Note

The selection stays when you change filters, so Move, Copy and Delete also act on selected images that the filters are currently hiding. The “N selected” badge counts all of them, and the Delete confirmation says how many are hidden.

Images with the same name

Annotations are saved under the image's name without its extension, so MaskLabel has to decide what “the same name” means. It depends on where the two images are:

  • Different splits or folders (for example train/dup_001.jpg and valid/dup_001.jpg, or the same filename in two folders of a folder of folders) — they are treated as two different images.

    When the dataset is imported or scanned, the repeated name is recorded, and from then on each copy has its own annotation files, named with the split or folder in front (train__dup_001.json, valid__dup_001.json).

    A name that does not repeat keeps its plain dup_001.json. Names are compared ignoring upper / lower case and accented-letter spelling differences, so A.jpg and a.jpg count as the same name. In a folder of folders the prefix is the folder name (image-collection folders get a short code added), and a name that already contains __ still works.

    A COCO import works the same way: the same name in two split folders imports both, each with its own annotation file. Each copy also keeps its own Train / Valid / Test tag (saved in dataset_splits.json under the annotation file's name, for example valid__a).

    Two files with the same name in one folder (a.jpg + a.png) share one annotation file, so only the first is imported. If the dataset was imported before and already has a shared a.json, only the first image is imported again; delete the annotations folder and import again to keep both. Anything an import skipped is listed in a notice when it finishes.

  • Names already saved — separating repeated names never renames anything. If a repeated name already has a plain dup_001.json (or its .cleared / .empty mark), its copies keep sharing it, and opening a folder of folders lists those names in an alert. Rename one copy to separate them. When two folders share a name, or two imported datasets both have a train split, the prefix gets a short code, for example images-a1b2c3__dup_001.json.

  • Same folder, different extension (a.jpg and a.png) — nothing can tell them apart, so they share one label file and one set of annotations. On a YOLO import only the first image's labels are used and you are warned about the others; Copy to Another Folder copies the first and skips the rest; if you delete one of them, its shared label file goes to the Trash with it.

  • Moving between splits — an image is never overwritten. If the target split already has an image, label or annotation file with the same name, or if two images in the folder share one label file, that image stays where it is and an alert says why. To move it, rename one of the two copies first. Moves that fail partway are undone, so an image is never separated from its label and annotations.

  • Plain folders — there is no split folder, so an image's Train / Valid / Test tag is saved by its name. Two images with the same name (for example in different subfolders) therefore share one tag.

Note

For a name that appears in more than one split, the Annotated and Empty filters, badges and counts go by the name, not by the individual copy: a copy can show as Annotated or Empty because another copy with that name is. What is saved and exported is always per copy: Mark as Empty skips an image only if that copy has masks, and a split export treats a copy as “marked empty” only if that copy carries the mark.

Importing and rescanning

  • File ▸ Rescan Folder (⌘R) picks up images and annotations that changed on disk. The scan and the count passes can be cancelled from the browser.

  • After a YOLO or COCO import, a banner appears above the grid when a photo is stored rotated (EXIF) or many label points fall outside the image. For rotated photos it offers the switch Labels were drawn without EXIF rotation; see Rotated photos (EXIF). The out-of-range warning is separate and the switch does not change it.

Tip

To make a small test set from a large one, filter the grid, press Edit Split, press Select All, then Copy to Another Folder….

Cache Files

MaskLabel runs in the macOS App Sandbox, so everything it keeps for itself lives inside its own container, ~/Library/Containers/com.masklabel.sam3, and the Library folders below are the ones inside it. Finder's Go to Folder… does not expand ~/Library/Caches to this location, so use the full paths shown here, or File ▸ Clear Cache… ▸ Show in Finder.

Outside your datasets, MaskLabel keeps its own files in three places: two folders in your Library — one safe to delete, one not — and its preferences file. Two more things are temporary: the model download's files in the container's tmp folder, and the window state macOS saves in Saved Application State. Inside each dataset's annotations folder there are also bookkeeping files; those are part of your work, not a cache.

  • ~/Library/Containers/com.masklabel.sam3/Data/Library/Caches/MaskLabel — safe to delete. Only rebuildable copies that make things faster.

  • ~/Library/Containers/com.masklabel.sam3/Data/Library/Application Support/MaskLabel — keep. The downloaded model and the annotations of collections.

  • The preferences file (~/Library/Containers/com.masklabel.sam3/Data/Library/Preferences/, named after the app) — keep, unless you want to reset settings. Shortcuts, display settings, the Open Recent list and its counts.

  • The annotations folder of each dataset — keep. Your annotations (see “Not cache: your annotations” below).

  • ~/Library/Containers/com.masklabel.sam3/Data/tmp — temporary; safe to delete while MaskLabel is quit. Only the leftovers of an interrupted model download.

  • ~/Library/Containers/com.masklabel.sam3/Data/Library/Saved Application State — macOS's own saved window state; safe to delete while MaskLabel is quit. See “Start fresh” below.

Caches folder — safe to delete

~/Library/Containers/com.masklabel.sam3/Data/Library/Caches/MaskLabel only holds copies of information that can be recomputed from your images and annotation files. Deleting the whole folder, or any folder inside it, loses nothing: it is rebuilt as you browse or reopen a folder, and the first open afterwards is just slower. macOS may also clear it by itself when the disk is nearly full. The folder only exists once you have browsed or opened something.

  • ThumbnailCache (.jpg files) — the Image Browser's thumbnails (small JPEGs, up to 240 px), so reopening a large folder doesn't redecode every full-size image.

    Usually the largest item here. At most once a day, about 10 seconds after the first thumbnails are shown at launch, MaskLabel tidies it: thumbnails of images that no longer exist at their old location (deleted, moved or renamed) and older versions of an edited image are dropped, then the thumbnails that haven't been shown for the longest time until it is back under roughly 1 GB (thumbnails you keep using are kept).

    Thumbnails of images in a folder MaskLabel cannot look into at that moment (a drive that isn't connected, or a folder it has no access to right now) are kept for when it returns.

    The 1 GB limit is applied only when this tidy-up runs, so in between it can grow past it. Delete it to free space or to force every thumbnail to regenerate.

  • FolderListing (.plist files) — the sorted list of image names found in each folder you've opened, so a folder opens before it is rescanned. One small file per folder; a folder with 100,000 images takes roughly several MB. Rebuilt on the next open.

  • SidecarIndex (.plist files) — a summary of each folder's saved annotation files (their classes and colors), used by the Image Browser's counts and filters. One file per folder, roughly several MB for 100,000 annotated images. Rebuilt on the next open, which then takes longer once.

  • HeaderCache (.json files) — each image's size and orientation, remembered for COCO imports and exports so they don't reopen every image. Small; entries for images that no longer exist are dropped at the next COCO import or export. Delete it and the next COCO import or export just reads the images again.

  • ImageBrowserFilters (.json files) — the Image Browser filters you last used for each folder. Tiny. Delete it and the filters reset to their defaults.

Note

The FolderListing, SidecarIndex, HeaderCache and ImageBrowserFilters files of a folder you haven't opened for about six months are removed automatically a few seconds after MaskLabel starts, so they don't pile up. You can still trash them yourself at any time. The in-memory caches (thumbnails, mask overlays, image sizes) and the model's GPU memory are not on disk at all: they are freed when you quit.

First launch: the model download

The first time MaskLabel starts, and any time the model folder is missing or incomplete (it has no config.json or no model.safetensors), it downloads the SAM3 model (float16) automatically from Hugging Face (huggingface.co) — there is no button to press and no question asked. The download is large (several GB at most; the exact size depends on the model), so a fast, stable connection helps. It needs an internet connection and enough free disk space for the download and the unpacked model at the same moment (roughly twice the download size until the zip is removed). MaskLabel checks the free space as soon as the download starts and stops at once with a message if there is not enough, so a nearly full disk does not waste the whole download. The model is not a cache: once installed it lives in Application Support and is kept.

  1. Downloading model… N% — the zip is saved in the container's temporary folder (~/Library/Containers/com.masklabel.sam3/Data/tmp).

  2. Unzipping model… — the zip is unpacked into a temporary folder with a long random name inside ~/Library/Containers/com.masklabel.sam3/Data/Library/Application Support/MaskLabel, then moved to sam3_float16. The zip and the temporary folder are removed afterwards.

  3. Loading model… — the weights are loaded into memory. From the next launch only this step happens.

  • If it fails (no internet, a dropped connection, too little free disk space, a damaged download) the toolbar shows a warning with the reason and a Retry button, and keeps it until you press Retry.

    A download that dropped continues where it stopped when possible. Cancel is shown next to the progress while downloading; after cancelling, Retry continues where it stopped when possible.

    Nothing is installed after a failure. Quitting while the model downloads stops the download at once and remembers where it stopped, so the next launch continues from there when possible (otherwise it starts again from the beginning).

  • To download again on purpose — quit, delete the sam3_float16 folder in ~/Library/Containers/com.masklabel.sam3/Data/Library/Application Support/MaskLabel, and start MaskLabel. This does not touch your annotations or collections.

  • If the model is installed but will not load (a damaged or incomplete download) the toolbar shows “Loading the model failed” with a Retry button. Retry downloads the model again and replaces the damaged folder; your annotations are not touched.

  • If the same failure keeps coming back — check that you are online and that the disk has several GB free (the message names the amount when space is the problem), empty the Trash, then press Retry.

Note

Leftovers after a quit, crash or power loss during the download — a .zip or CFNetworkDownload_….tmp file in the temporary folder, or a folder with a long random name inside Application Support — are only partial downloads. MaskLabel removes them by itself a few seconds after starting once they are over an hour old; you can also delete them while it is quit.

First launch and later launches: the window

First launch — there is no saved window yet, so the window opens centered on your main screen at 90% of the screen's usable area (the part not covered by the menu bar and Dock), but no larger than about 1280 × 820 and never smaller than 600 × 600. Those numbers describe the window's content, so the window itself is a little taller because of the title bar and toolbar.

From the second launch on — the window opens where and how big you left it. macOS saves the window's size and position whenever you move or resize it, as an NSWindow Frame … entry in the preferences file; if the screen it was on is no longer connected, macOS moves the window onto a screen that exists. macOS also keeps its own saved window state in Saved Application State. To go back to the first-launch size, follow “Start fresh” below (or the window-only note under it).

Application Support folder — keep

~/Library/Containers/com.masklabel.sam3/Data/Library/Application Support/MaskLabel holds things MaskLabel cannot rebuild by itself. Don't delete it, or anything inside it, unless you are sure.

  • sam3_… model folders (one per model size, each with config.json and model.safetensors) — the downloaded SAM 3 model. Deleting one doesn't harm your data, but MaskLabel then has to download that model again (a large download, internet required) before Find Objects and clicking-to-mask work. The model you aren't using can be deleted to free space.

  • Collections — one folder per collection you opened by dropping or choosing several images or folders. Each holds the list of those images and folders and the annotations you made on the collection. Deleting Collections, or one folder inside it, permanently deletes those annotations. Your original images are never touched. To remove a collection you no longer need, delete just its folder.

Other things MaskLabel stores

  • Preferences file — the window's size and position, your shortcuts, Mask Opacity, Polygon / Pixels mode, Simplify level, Pixels Mask Stroke, the Refine Boxes options, the split-export choices, the Open Recent list with the image / annotation / empty / split counts it shows (the 10 most recent folders can be reopened; counts for up to 50 folders are kept), and the saved access to the folder to reopen at launch.

    It is not a cache; Where Settings Are Stored lists everything in it. To reset it, follow “Start fresh” below: afterwards Open Recent is empty, every shortcut is back to its default, and the window opens at its first-launch size again.

  • Temporary files — while a model downloads, the partly downloaded file (named CFNetworkDownload_….tmp) and then its zip are kept in the container's temporary folder (~/Library/Containers/com.masklabel.sam3/Data/tmp); the zip is removed once it is unpacked, or if the download or unpacking fails. macOS empties that folder by itself, and MaskLabel removes such leftovers over an hour old a few seconds after it starts — except the partial file of a download you quit, which is kept so the next launch can continue it.

    If macOS or you remove it, the download simply starts again from the beginning. A leftover .zip or .tmp there is safe to delete while MaskLabel is quit.

    File ▸ Clear Cache… does not list this folder, the preferences file or the saved window state. If a download was interrupted by a crash or power loss, a stray folder with a long random name may remain inside ~/Library/Containers/com.masklabel.sam3/Data/Library/Application Support/MaskLabel; it is only a partial download and is safe to delete.

  • Folders macOS adds to the container — macOS and system frameworks may create folders of their own inside ~/Library/Containers/com.masklabel.sam3/Data/Library, for example Caches/com.masklabel.sam3 (system caches). MaskLabel does not keep your data there; they are rebuilt when needed, and anything under Caches can be deleted while MaskLabel is quit. File ▸ Clear Cache… does not list them.

  • A hidden tag on exported images — an export records on each image it writes which source it came from, so the next export to the same place skips images that haven't changed. The tag lives on the file and goes with it. There is nothing to manage.

Not cache: your annotations

Your annotations are never in the Caches folder. A folder's annotations live in its annotations folder next to your images (or in the folder you chose with Change Annotations Folder…). That folder is your work, not a cache: don't delete it, or anything inside it, unless you want the annotations gone. It holds:

  • one .json file per annotated image, plus the mask PNGs of Pixels masks

  • classes.json (classes and colors) and dataset_splits.json (train / valid / test tags)

  • .empty and .cleared files — small empty marker files named after the image, next to its .json. .empty means you marked the image as empty (reviewed, no objects), so export writes it as a background image. .cleared (YOLO datasets only) means you deleted all of an imported image's labels, so reopening the folder does not bring the original labels back and export empties its label file. Saving a mask on the image removes either marker. Deleting one by hand simply undoes that status.

  • hidden files whose names start with a dot: .masklabel_split_collisions.json (which image names appear in several splits — without it those images' annotation files can't be told apart) and .masklabel_yolo_import.json (import settings such as the EXIF switch). In Finder, press Command-Shift-period to show hidden files.

  • .box_refine_backup and .folder_find_backup (hidden folders) and dataset_splits.json.corrupt — backups made by Refine Boxes, by Find Objects in Folder and by split-file recovery; see “Backups and leftovers” below.

Backups and leftovers

These are not caches, but you may come across them and wonder whether they can go.

  • original_labels_backup (YOLO) and original_annotations_backup (COCO) — next to your dataset. Made once, before the first export, and never overwritten. They can be large. Once you have checked the export is right you can delete them; the next export then backs up the labels as they are at that time.

  • .box_refine_backup — hidden, inside the annotations folder. The first version of each annotation changed by Refine Boxes. Safe to delete once you are happy with the refinement.

  • .folder_find_backup — hidden, inside the annotations folder. The first version of each annotation file that Find Objects in Folder added objects to. Safe to delete once you are happy with the result.

  • dataset_splits.json.corrupt — a copy of a split file MaskLabel could not read. Keep it until you have checked your train / valid / test tags.

  • Files ending in .partial or .tmp — left over from a backup or export that was interrupted. Safe to delete.

Start fresh — reset settings and window

Starting fresh puts MaskLabel back to how it was the first time you ran it: default shortcuts and settings, an empty Open Recent list, no folder reopened at launch, and the window at its first-launch size. Your annotations, collections and the downloaded model are not touched. The app's id is com.masklabel.sam3.

  1. Quit MaskLabel (⌘Q).

  2. Open Terminal and run defaults delete ~/Library/Containers/com.masklabel.sam3/Data/Library/Preferences/com.masklabel.sam3. This removes the preferences file, ~/Library/Containers/com.masklabel.sam3/Data/Library/Preferences/com.masklabel.sam3.plist. Use this full path: the short form defaults delete com.masklabel.sam3 may look at a different file than the sandboxed app uses. If it says the domain does not exist, there is nothing to reset.

  3. Run killall cfprefsd. macOS keeps preferences in memory, and without this it can write the old values back when it next saves. It restarts by itself.

  4. Start MaskLabel. It opens at its first-launch size with default settings.

  5. If the window still opens at its old size or position, macOS is restoring its own saved window state. Quit MaskLabel, run rm -rf ~/Library/Containers/com.masklabel.sam3/Data/Library/Saved\ Application\ State/com.masklabel.sam3.savedState, and start it again.

Note

To reset only the window and keep your settings: defaults read ~/Library/Containers/com.masklabel.sam3/Data/Library/Preferences/com.masklabel.sam3 | grep "NSWindow Frame" lists the saved window frames. Delete just that entry with defaults delete ~/Library/Containers/com.masklabel.sam3/Data/Library/Preferences/com.masklabel.sam3 "<the name it shows>", then run killall cfprefsd.

Tip

Never delete the whole ~/Library/Containers/com.masklabel.sam3 folder to start fresh. It also holds Application Support: the downloaded model and your Collections, with their annotations.

Fresh run — pick how fresh

Quit MaskLabel (⌘Q) before any of these. Every level leaves your images and your datasets' annotation folders alone.

  • Level 1 — empty the caches. File ▸ Clear Cache…, tick everything, Delete Selected. Nothing is lost; the first open of each folder is slower. Fixes odd counts, thumbnails and filters.

  • Level 2 — also reset settings and the window. Level 1, then follow “Start fresh” above. Shortcuts, Open Recent, display settings and the window size go back to defaults, and MaskLabel forgets which folders it may open, so you pick them again.

  • Level 3 — also forget collections and the model. Level 2, then in ~/Library/Containers/com.masklabel.sam3/Data/Library/Application Support/MaskLabel delete the sam3_… model folder (it downloads again on the next launch) and, only if you are sure, Collections — that permanently deletes the annotations you made on collections. Export them first. The next launch then behaves like the very first one: the model downloads automatically again (see First launch: the model download) and the window opens at its first-launch size.

Note

Do not trash the whole ~/Library/Containers/com.masklabel.sam3 folder for a fresh run: it contains Application Support, so it is Level 3 plus the collections' annotations in one step.

Which should I delete?

  • To free disk space — ThumbnailCache first; it is usually the largest (up to about 1 GB). Then FolderListing and SidecarIndex if you have opened very large folders.

  • A folder shows images that were added or removed outside the app — press ⌘R (Rescan Folder). It ignores the FolderListing cache and re-reads the disk, so you never need to delete a cache for that.

  • Thumbnails look out of date or wrong — delete ThumbnailCache.

  • The Annotated / Unannotated counts or the class filter look wrong — press ⌘R first; if that doesn't help, delete SidecarIndex and reopen the folder.

  • To reset the Image Browser's filters — delete ImageBrowserFilters.

  • Everything else — leave it alone.

How to check the size and remove the cache

Easiest: choose File ▸ Clear Cache…. The window lists each cache folder with its size; tick what you want gone and press Delete Selected. You can do this while MaskLabel is running, and it takes effect immediately — including the folder lists and annotation summaries MaskLabel keeps in memory for the folders you opened most recently. Or do it by hand in Finder:

  1. Quit MaskLabel, so nothing is written while you delete.

  2. In Finder choose Go ▸ Go to Folder… (or hold ⌥ and open the Go menu to show Library) and enter ~/Library/Containers/com.masklabel.sam3/Data/Library/Caches.

  3. To see how much space it takes, select the MaskLabel folder and press ⌘I (Get Info), or look inside it item by item. In Terminal, du -sh ~/Library/Containers/com.masklabel.sam3/Data/Library/Caches/MaskLabel/* lists the size of each item.

  4. Move the MaskLabel folder to the Trash — or open it and trash only the items you want gone. The files inside each item have hashed names, so trash a whole item (such as SidecarIndex) rather than single files. In Terminal, rm -rf ~/Library/Containers/com.masklabel.sam3/Data/Library/Caches/MaskLabel/ThumbnailCache removes just the thumbnails.

  5. Empty the Trash to free the space, then reopen MaskLabel. The first open of each folder is slower while the caches are rebuilt.

Note

To find the folders from Terminal: find ~/Library/Containers -maxdepth 6 -name MaskLabel -type d. File ▸ Clear Cache… and its Show in Finder button always open the right one.

Tip

The quickest way is File ▸ Clear Cache…: it shows the size of each cache folder, lets you tick the ones to delete, and removes them. It never touches your annotations, backups, the downloaded model or your collections.

Keyboard Shortcuts

Most shortcuts can be changed: click the toolbar's Customize Shortcuts button (or press K, so you don't have to scroll the toolbar to reach it), click a shortcut, and press the new keys. Recording a new key is cancelled automatically if you switch to another app or window.

The panel detects whether you have a US or Japanese (JIS) keyboard so the defaults for Zoom In (and the other punctuation keys) land on the right physical keys; you can override that in the panel. Other layouts (German, French, …) aren't detected: shortcuts follow the physical key, so on those keyboards re-record Zoom In and the other punctuation keys, or use the keypad + / − or ⌘= / ⌘- for zoom. Keypad digits count as the same key as the top-row digits, so a keypad key and its top-row twin can't be bound separately.

Conflicts and reserved keys

  • Already taken — a shortcut that is already used is refused with a message saying who uses it.

  • Two shortcuts on one key anyway (for example after switching the keyboard layout, or when an update adds a new default) — your own choice is kept, the other one is cleared to "None", and the panel tells you which. Click it to pick another key. A shortcut cleared this way returns by itself once its key is free again (for example after you switch the keyboard layout back).

  • Reserved keys — a custom shortcut that sits on a reserved key (for example after an import, or after an update reserved more keys) is reset the same way. Standard macOS menu keys such as ⌘N, ⌘` and ⌃⌘F can't be assigned.

  • fn (Globe) + a key belongs to macOS (for example fn+F enters full screen) and never triggers a shortcut here, so pressing fn+F no longer runs Find Objects with AI; it can't be assigned either.

  • Menus — customizable shortcuts are not listed in the File, Edit or View menus, because a menu can't show a key you have changed; they appear only in Customize Shortcuts (the fixed ones stay in the menus).

Reset, export and import

Reset all… at the bottom of the panel restores every shortcut to its default. Export… and Import… next to it save your setup to one JSON file and load it back, so you can use the same setup on another Mac.

  • What is saved — your custom shortcuts, the keyboard layout choice, and the settings that are remembered between launches: Mask Opacity, Polygon / Pixels mode, the Simplify level and Pixels Mask Stroke, plus Hover Mask Color, the Refine Boxes options, the Find Objects in Folder options, the export result panel switch and the split-export choices.

  • Importing replaces your current customizations and applies those settings straight away. Older shortcuts-only files still import (they leave the other settings alone).

  • Not saved — Hide Mask Hover, Open Editor on Layer Click and the Contrast / Brightness / Background Darkness sliders are viewing toggles: they are not saved or exported and start fresh each launch.

  • Problem files — a file made by a newer version of the app is refused with a message, and a damaged one is reported as such.

  • US and Japanese keyboards — a file moves between them (the physical keys are the same), but its key labels may look different until you re-record them.

Note

Where your shortcuts are stored, and exactly what Export… and Import… carry, is listed in Where Settings Are Stored.

The one exception is Annotation Editor Delete, which has to work with text in the field, so it always needs ⌘, ⌃ or ⌥.

The ⌥ (Option) key

⌥ is also a modifier you hold while clicking or dragging on the canvas. These are all the places it is used (none of them is a shortcut you can reassign):

  • Edit polygon points from any tab — with a Polygon-mode mask selected and the Draw, Erase or SAM tab open, hold ⌥ to edit its points without leaving the tab: click a point to delete it, drag a point to move it, and drag along an edge to add a point. It does not apply while an outline is being drawn or while a SAM session with points is in progress, and (like the Points tab itself) it only works while Masks in Display Options is set to Full — with Half or Hidden the points aren't shown, so they can't be grabbed.

  • Drag a box — hold ⌥ while you drag, or when you release the box, to remove that area instead of adding it. The box (and its live preview) is green when it will add and red when it will remove.

  • Refine with clicks (SAM tab, and after a box) — ⌥ flips a click: outside the preview it adds a negative point, inside it adds a positive one. The first point is always positive, so ⌥ only applies from the second point on. The cursor shows + or − and updates as you press or release ⌥.

  • Zoom with the scroll wheel — hold ⌥ (or ⌘) and scroll to zoom around the pointer instead of panning.

  • Find Similar — ⌥-drag a box to mark a not-example (red) instead of an example (green).

  • Menu — ⌥⌘O is Change Annotations Folder (fixed). ⌥⌘H and ⌥⌘M belong to macOS and can't be assigned either.

The ⇧ (Shift) key

⇧ also changes what a click, a drag or an arrow key does. These are all the places it is used apart from the shortcuts listed above (none of them is a shortcut you can reassign):

  • Refine with several SAM points — ⇧-click on the SAM tab (or drag a box around the object) starts a multi-point refinement instead of a one-shot click. The ⇧ is only needed for the first click; after that every click adds a point, and ⌥ flips it to a negative one.

  • Select polygon points — ⇧-click a point to add it to or remove it from the selection. ⇧-drag a selection box to add its points to the current selection instead of replacing it, and a ⇧-click on empty space keeps the selection.

  • Nudge points — with points selected, an arrow key moves them 1 image pixel and ⇧ + an arrow moves them 10.

  • Inside shortcuts — Zoom In is ⇧= (US) or ⇧; (JIS) by default, and the fixed Redo (⌘⇧Z) and Deselect All (⌘⇧A) shortcuts, and the default Close Folder (⌘⇧W), use ⌘⇧; ⇧N and ⇧/ are customizable defaults.

Where Settings Are Stored

MaskLabel keeps your choices in a few different places, and the place decides what travels with you: to another Mac (the settings file), with a dataset (its annotations folder), or nowhere at all (the setting starts fresh at every launch).

The app's preferences file — this Mac only

These are stored in the app's macOS preferences (user defaults) file, ~/Library/Containers/com.masklabel.sam3/Data/Library/Preferences/com.masklabel.sam3.plist. It belongs to this Mac and this user account, not to a dataset.

  • Shortcuts — your customized and cleared shortcuts, and the keyboard layout choice (Auto-detect / US / Japanese). Included in the settings file.

  • Mask settings — Mask Opacity, Hover Mask Color, Polygon / Pixels mode, the Simplify level and Pixels Mask Stroke. Included in the settings file.

  • Refine Boxes options — the minimum size, confidence, margin and centre-point options. Included in the settings file.

  • Find Objects in Folder options — the confidence and the two skip switches are included in the settings file; the recent names are not.

  • Export result panel — whether the result panel is shown after an export (the checkbox next to the Export button). Included in the settings file.

  • Split-export choices — in the YOLO and COCO export sheets: Shuffle, Include unannotated images, Resize and its Max dimension, and Convert pixel masks to polygons. Included in the settings file. (The image limit and the destination folder are not.)

  • Folders — the Open Recent list with its counts (up to 50 folders), and the saved access to the folder and image to reopen at launch. That access is specific to this Mac. Not in the settings file.

  • Window and panels — the window's size and position, the Mask Options panel height, and the last Help topic you read. Not in the settings file.

  • Housekeeping — where an interrupted model download stopped (so it can continue) and when the thumbnail cache was last tidied. Not in the settings file.

Note

To wipe everything in this list, follow “Start fresh” in Cache Files.

The dataset's annotations folder — goes with the dataset

Some settings belong to the dataset rather than to your Mac. They are stored in its annotations folder, next to your annotations, so they follow the dataset when you copy or move it. None of them is part of the settings file.

  • classes.json — the classes and their colors.

  • dataset_splits.json — the train / valid / test tags.

  • .masklabel_yolo_import.json — import settings such as the EXIF switch.

  • .empty and .cleared files — the images you marked as empty, and the images whose imported labels you removed.

The settings file — to move to another Mac

File ▸ Export Settings… writes one JSON file (named MaskLabel-settings.json by default) and File ▸ Import Settings… reads it back. The Customize Shortcuts panel has the same two buttons, Export… and Import…. The result message appears in that panel, which opens by itself after a menu export or import.

  • In the file — your customized and cleared shortcuts, the keyboard layout choice, Mask Opacity, Hover Mask Color, Polygon / Pixels mode, the Simplify level, Pixels Mask Stroke, the Refine Boxes options, the Find Objects in Folder options (confidence and the two skip switches), the export result panel switch and the split-export choices (Shuffle, Include unannotated images, Resize and Max dimension, Convert pixel masks to polygons).

  • Not in the file — Open Recent and the folder to reopen at launch, window and panel sizes, and everything in the dataset's annotations folder. To carry those over, copy the annotations folder itself.

  • Importing replaces your current shortcut customizations with the file's — a shortcut the file doesn't customize goes back to its default — and applies the other settings straight away. An older shortcuts-only file still imports and leaves the other settings alone. A file made by a newer version of the app is refused, and a damaged one is reported as such.

Not saved anywhere

These are viewing toggles. They start fresh at every launch on purpose, so a forgotten switch can't make the app look broken after a restart. They are not in the preferences file, the settings file or the dataset.

  • Contrast, Brightness and Background Darkness

  • Mask Visibility (Full / Half / Hidden)

  • Hide Mask Hover

  • Open Editor on Layer Click

The Caches folder — can be deleted

The Image Browser's filters for each folder are kept in the Caches folder (ImageBrowserFilters), together with thumbnails and folder lists. It is all rebuildable; deleting it only resets those filters. See Cache Files.

Tip

To set up another Mac the same way: Export Settings… here, Import Settings… there, then copy the datasets' annotations folders.
